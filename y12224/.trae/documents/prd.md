## 1. 产品概述

养老机构床位押金本地管理服务，解决转房补差、短住退押、护理变更等场景下财务人员需手动翻阅入住档案、押金流水和结算说明、容易遗漏的问题。系统以押金账本为主线，将入住档案、床位状态、费用试算归到同一件事上，实现新增、复核、状态推进和导出的全流程数据闭环。

- 目标用户：养老院财务人员、行政管理人员
- 核心价值：一条线索串起所有材料，明确"哪份材料触发的、卡在哪里、下一步该补什么"

## 2. 核心功能

### 2.1 用户角色

| 角色 | 进入方式 | 核心权限 |
|------|----------|----------|
| 财务人员 | 本地登录 | 押金收退、费用试算、结算说明生成与导出 |
| 行政人员 | 本地登录 | 入住档案管理、床位分配、状态推进 |

### 2.2 功能模块

1. **押金账本页**：押金总览、流水明细、状态追踪
2. **入住档案页**：老人信息、护理等级、床位分配、关联押金
3. **结算中心页**：转房补差、短住退押、护理变更的处理流程与结算说明生成
4. **床位总览页**：床位状态一览、房间类型与费用关联

## 3. 核心流程

### 3.1 新增入住流程
1. 录入老人基本信息、选择护理等级
2. 分配床位，系统自动关联房间类型费用标准
3. 收取押金，创建押金账本
4. 状态推进：登记→押金已收→在住

### 3.2 转房补差流程
1. 提交转房申请（含原房号、新房号、转房原因）
2. 系统自动计算房间差价，生成费用试算
3. 财务确认补差金额，收取或退还差价
4. 更新床位状态和押金账本
5. 状态推进：申请→试算→补差→完成

### 3.3 短住退押流程
1. 提交退住申请
2. 系统按实际入住天数试算费用
3. 计算应退押金 = 押金 - 实际费用
4. 财务复核，确认退押
5. 状态推进：申请→费用结算→退押→完成

### 3.4 护理变更流程
1. 提交护理等级变更申请
2. 系统按新旧等级差计算费用变化
3. 如需补缴/退还，生成对应押金流水
4. 状态推进：申请→费用调整→确认→完成

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：暖灰色底色 + 青绿色强调色（传达"关怀+财务可信"）
- 次要色：琥珀色用于警示/待办，翡翠绿用于完成状态
- 按钮风格：圆角微阴影，主操作实色填充，次操作描边
- 字体：正文用 Source Han Sans / Noto Sans SC，数据用等宽字体 JetBrains Mono
- 布局风格：左侧导航 + 右侧内容区，卡片式模块，顶部状态条
- 图标风格：Lucide 线性图标，统一 20px

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 押金账本页 | 账本总览 | 顶部统计卡片（总押金/在住/待办），下方表格，行内状态标签 |
| 押金账本页 | 流水明细 | 时间线式流水列表，每条标注触发原因图标+来源链接 |
| 押金账本页 | 状态推进条 | 横向步骤条，当前阶段高亮，可点击推进按钮 |
| 入住档案页 | 档案列表 | 搜索栏+筛选器+表格，支持按姓名/房号/护理等级筛选 |
| 入住档案页 | 档案详情 | 左侧信息卡+右侧标签页（押金/变更/床位） |
| 结算中心页 | 事件列表 | 卡片列表，每张显示事件类型、老人姓名、当前阶段、下一步 |
| 结算中心页 | 结算说明 | 左侧实时预览+右侧数据来源标注（可点击追溯） |
| 床位总览页 | 床位看板 | 楼层标签切换，房间格子布局，颜色区分状态 |

### 4.3 响应式

- 桌面优先（1920/1440/1280），表格和看板在宽屏下充分展示
- 平板适配：侧边栏可收起，卡片单列排列
- 手机端暂不支持（养老院办公场景以桌面为主）

### 4.4 3D 场景

不适用
