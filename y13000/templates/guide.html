📘 再保分摊批次复核 · 使用指引

→ 开始使用
📍 排班同事快速上手（5分钟）

一、系统功能分布

  • 📋 批次列表（首页）：看所有待复核批次，做确认/撤回/负数冲正操作
  • 📧 审批邮件：放材料的地方，所有审批邮件原始内容都在这里
  • ⚠️ 异常队列：看异常的地方，同一笔钱被两个口径认走会出现在这里
  • 📜 操作历史：老许临时改过的判断、补录改判都在这里能看到
  • 📘 使用指引：就是本页面

二、日常复核流程

  1. 打开批次列表，看顶部统计卡片，"待复核"和"异常待处理"数字要清掉
  2. 点击批次号进入详情页，核对：金额、口径、保单号、关联的审批邮件
  3. 没问题 → 点"确认"，可加备注；如果是老许特别交代的，勾"人工特殊处理"
  4. 有问题：
    • 需要退回 → 点"撤回"，填撤回原因和下一步（如：退回运营重提）
    • 需要负数冲正 → 点"负数冲正"，必须填原因和下一步，系统自动记人工改判
    • 补了新材料结论变了 → 点"补录改判"，填改判原因、新状态、新材料备注
  5. 如果顶部导航栏"异常队列"有红色数字，务必点进去处理

三、放材料的地方（邮件导入）

  1. 从邮箱导出审批邮件：单个邮件存 .eml 或 .txt，多个邮件汇总存 .csv
  2. 在批次列表或审批邮件页面点"导入审批邮件"，上传文件即可
  3. 系统会尝试自动识别批次号和金额，但不会清洗原始内容，原文完整保留
  4. 如需手动关联邮件和批次：在审批邮件页点"关联批次"，输入批次ID即可

四、看异常的地方

  • 异常规则：同一金额+同一保单号+同一日期下出现多个不同口径，即判定为"同笔多口径冲突"
  • 异常队列会列出冲突的所有批次，点击可跳转详情核对
  • 处理异常时必须填写处理说明（保留哪个口径、依据是什么）
  • 可随时点"重新检测异常"按钮扫描最新数据

五、重新导出数据

  • 批次列表页右上角 → "导出批次"：导出全部批次及原始数据（CSV）
  • 操作历史页右上角 → "导出全部历史"：导出所有操作记录，含改判原因和原始快照
  • 审批邮件页右上角 → "导出全部"：导出所有邮件及原始内容
🔑 关于"留痕"的设计说明

为什么这么设计？

  • 审批邮件保留原始来源：每个邮件的 raw_content 字段存储完整原文，不做任何清洗，正文提取仅做展示用。脏数据原样保留，方便追溯。
  • 批次也有 raw_data：导入时每一行CSV原始JSON都存下来，后续只改状态不改数据。
  • 每次操作存快照：OperationHistory 表的 raw_snapshot 字段是操作那一刻的完整JSON快照，含时间戳，不可篡改。
  • 负数冲正强制留痕：必须填"改判原因"+"下一步操作"，自动标记 is_manual_override=True，历史页一眼能看出是人工改判的。
  • 补录改判完整对比：历史时间线展示"原备注→新备注"、"原状态→新状态"、改判原因、下一步，一目了然。
  • 老许临时改判：确认操作勾"人工特殊处理"，历史记录会标红"人工改判"标签。

导入CSV模板字段参考

  • 批次数据CSV：批次号、金额、币种、口径、保单号、业务类型、发生日期（中文或英文列名均可）
  • 邮件CSV：主题、发件人、收件人、日期、正文、批次号、金额（中文或英文列名均可）
