# 码头危险品库空间复核系统

> 工业级危险品仓库空间复核平台 —— 坏数据自动隔离、三套表述数据同源、原始痕迹完整保留

---

## 快速开始（2 步操作）

### 第 1 步：启动系统

```bash
npm install
npm run dev
```

浏览器打开终端输出的地址（默认 `http://localhost:5173`，如端口被占用会自动顺延）进入复核主界面。

### 第 2 步：日常复核

1. 顶部工具栏切换**视角**（按库区 / 按危险等级 / 按时间轴）
2. 点击场景图中的**库位**，查看侧边明细和底部说明
3. 点击「**导出截图**」一键导出当前视角的完整复核画面

> ✅ 场景标注、侧边明细、截图说明 —— 三套话数据同源，表述一致

---

## 坏材料来了怎么办？（重点看这里）

当评审批注不齐、时间轴缺段等坏数据出现时，按以下顺序排查：

### 🔴 第一步：看右上角「坏数据专区」按钮

- 按钮上的**红色角标数字** = 当前坏数据总数
- 数字在**跳动闪烁** = 有高优先级异常

### 🟠 第二步：进入坏数据专区

点击「坏数据专区」按钮，页面分左右两栏：

| 区域 | 看什么 | 怎么看 |
|------|--------|--------|
| 左侧列表 | 所有异常记录 | 按类型筛选（时间缺段 / 批注不齐），按库位搜索 |
| 右侧查看器 | **原始数据原貌** | 红色高亮 = 有问题的字段，**不做任何清洗** |

> 📌 每一条坏数据都标了**原始来源**（哪个文件第几行），顺着找过去就能核对

### 🟡 第三步：判断处理

1. **先核对原始文件** —— 确认数据是不是真的缺了
2. **能补就补** —— 联系数据提供方补录原始数据
3. **补不了的** —— 在评审批注里注明原因，保留痕迹

### 🟢 核心原则

- 坏数据**不混入**正常复核结果
- 原始数据**不修改**、**不清洗**
- 每条异常都能**追溯到具体行、具体对象**

## 主要功能

- 🗺️ **库区场景图**：可视化库位布局，状态一目了然
- 🔄 **三种视角**：按库区 / 按危险等级 / 按时间轴切换
- 🔍 **筛选过滤**：库区、等级、状态多维筛选
- 📋 **侧边明细**：基本信息、空间数据、评审批注、时间轴记录
- 📝 **底部说明**：自动生成截图配套说明文字
- 📸 **一键导出**：当前视角完整截图导出
- ⚠️ **坏数据专区**：时间轴缺段、评审批注不齐单独拎出
- 🔗 **原始追溯**：每条坏数据关联原始来源，保留脏数据痕迹

## 技术栈

- React 18 + TypeScript + Vite
- Tailwind CSS 3
- Zustand 状态管理
- Lucide 图标
- html2canvas 截图导出
