# 门店现金短款调查

> 目标：聚焦口径一致、筛选联动、分项稽核、结论导向报告，不做大而全。

---

## 一、第一次使用（从空目录开始）

### 1. 前置条件

- 电脑安装了 **Python 3.8 或更高版本**
  - 验证方法：打开「终端」，输入 `python3 --version`，能看到版本号即可

### 2. 拉取代码 / 准备目录

把项目文件放到本地任意目录，例如 `/Users/你的名字/work/cash-shortage/`。

目录结构应该是这样的：

```
cash-shortage/
├── cash_shortage/              # 源码目录（不用动）
│   ├── config/                 # 口径与配置定义
│   ├── data/                   # 数据加载与筛选
│   ├── checks/                 # 分项稽核逻辑
│   └── report/                 # 报告导出
├── sample_data/                # 示例数据（跑通流程用）
│   └── cashier_data.csv
├── tests/                      # 自动化测试
├── output/                     # 报告生成后会自动出现在这里
├── requirements.txt            # 依赖列表
└── run_audit.py                # 主入口脚本（执行这个）
```

### 3. 安装依赖

打开终端，进入项目目录，执行：

```bash
cd /Users/你的名字/work/cash-shortage
python3 -m pip install -r requirements.txt
```

> 提示：如果 `pip` 下载慢，可以在后面加国内镜像：
> `python3 -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

## 二、跑通示例（5分钟）

### 步骤 1：看一眼示例数据

`sample_data/cashier_data.csv` 是一份准备好的模拟数据，列名就是日常拿到的原始流水列名：

| 门店编号 | 门店名称 | 交易日期 | 班次 | 收银员 | 交易类型 | 金额 | 支付方式 | 流水号 | 是否签字确认 | 备用金类型 |
|---------|---------|---------|------|--------|---------|------|---------|--------|-------------|-----------|

里面预置了 3 类问题：
- 2 笔退款未签字
- 2 笔备用金班次错配
- 4 笔流水重复

### 步骤 2：运行示例

在终端执行：

```bash
python3 run_audit.py -i sample_data/cashier_data.csv --date-start 2026-05-01 --date-end 2026-05-03
```

你会看到类似输出：

```
✅ 稽核完成
📊 筛选后记录数: 15
⚠️  发现风险: 8 笔, 涉及 1533.5 元
   - 退款漏签: 2 笔 / -184.0 元
   - 备用金错班: 2 笔 / 800.0 元
   - 流水重复: 4 笔 / 917.5 元
📄 报告已生成: output/门店现金短款调查报告_2026-05-31.xlsx
```

### 步骤 3：打开报告看看

去 `output/` 目录打开刚生成的 Excel，里面有 7 个工作表：

| 工作表 | 给谁看 | 内容 |
|--------|--------|------|
| 概览 | 所有人 | 总体结论、分项汇总表 |
| 退款漏签 | 稽核同事 | 逐条明细 + **认定理由** |
| 备用金错班 | 稽核同事 | 逐条明细 + **认定理由** |
| 流水重复 | 稽核同事 | 逐条明细 + **认定理由** |
| 全部风险明细汇总 | 转外行同事看 | 合并所有风险，每条都写清「为什么算风险」 |
| 筛选后标准流水(备查) | 稽核内部 | 口径统一后的流水 |
| 原始流水(转同事核对用) | 转同事核对 | **原始数据，未做口径转换** |
| 口径说明 | 所有人 | 字段口径 + 检查规则，方便对方理解 |

> 💡 外行同事看「全部风险明细汇总」就行，列名都是中文，每条都有「认定理由」说明为什么有风险。

## 三、日常使用（跑真实数据）

### 1. 准备你的数据

把门店的收银流水导出成 CSV 或 Excel，**列名必须和下面一致**（口径定义在 `cash_shortage/config/specs.py`，需要改列名可以去那里调整）：

| 原始列名 | 说明 | 必填 |
|---------|------|------|
| 门店编号 | 如 S001 | 是 |
| 门店名称 | 如 朝阳店 | 是 |
| 交易日期 | 如 2026-05-01 | 是 |
| 班次 | 早班/中班/晚班 | 是 |
| 收银员 | 姓名或工号 | 是 |
| 交易类型 | 销售/退款/备用金存取 等 | 是 |
| 金额 | 数字，退款为负 | 是 |
| 支付方式 | 现金/微信/支付宝 等 | 是 |
| 流水号 | 收银系统唯一编号 | 是 |
| 是否签字确认 | 是/否/已签字 | 退款检查用 |
| 备用金类型 | 早班备用金交接/中班备用金交接 等 | 备用金检查用 |

### 2. 运行命令，灵活筛选

```bash
python3 run_audit.py \
  -i 你的流水文件.csv \
  --date-start 2026-05-01 \
  --date-end 2026-05-31 \
  --store S001 --store S002 \
  --shift 早班 --shift 中班 \
  --cashier 张三 \
  --prepared-by "张稽核"
```

**常用参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-i` / `--input` | 收银流水文件路径（必填） | `-i data/may_data.csv` |
| `-o` / `--output-dir` | 输出目录（默认 `output/`） | `-o /Users/xxx/Desktop/报告` |
| `--date-start` | 起始日期（YYYY-MM-DD） | `--date-start 2026-05-01` |
| `--date-end` | 结束日期 | `--date-end 2026-05-31` |
| `--store` | 指定门店（可多次） | `--store S001 --store S002` |
| `--shift` | 指定班次（可多次） | `--shift 早班 --shift 中班` |
| `--cashier` | 指定收银员（可多次） | `--cashier 张三` |
| `--trans-type` | 指定交易类型 | `--trans-type 退款` |
| `--payment` | 指定支付方式 | `--payment 现金` |
| `--prepared-by` | 报告编制人 | `--prepared-by "连锁门店稽核组"` |
| `--no-keep-raw` | 不保留原始流水（默认保留） | |

### 3. 筛选一变，报告自动同步

每次运行都会根据你传的筛选条件重新：
1. 筛选数据
2. 跑 3 项稽核
3. 生成完整报告

图表 + 明细 + 结论 都基于同一筛选结果，**口径完全一致**。

## 四、3 项稽核规则说明

### 1️⃣ 退款漏签（高风险）
- **判定规则**：交易类型 = 「退款」，且「是否签字确认」≠「是/已签字/Y」
- **认定理由示例**：「该笔为退款交易，金额-56.0元，但系统中「是否签字确认」字段为「否」，非「是/已签字」，属于退款漏签风险。」

### 2️⃣ 备用金错班（中风险）
- **判定规则**：交易类型包含「备用金」，且「备用金类型」中标注的班次（早班/中班/晚班）≠ 实际当班班次
- **认定理由示例**：「该笔为备用金交易，类型标注为「早班备用金交接」，但实际当班为「中班」，班次不匹配，属于备用金错班风险。」

### 3️⃣ 流水重复（高风险）
- **判定规则**：同一流水号出现多次，**或** 同一门店+同一日期+同一班次+同一金额+同一交易类型的记录重复
- **认定理由示例**：「该笔流水号「T20260502001」在同一数据范围内出现 2 次，或与同一门店同一班次同金额同类型的其他交易重复，属于流水重复风险。」

> ✅ 3 类问题**分开 sheet + 分开汇总**，不会合并成一个笼统的「风险」。

## 五、给外行同事导出报告时

直接发 `output/门店现金短款调查报告_YYYY-MM-DD.xlsx` 即可，对方重点看：

1. **概览** 页：一眼看到总体结论
2. **全部风险明细汇总** 页：每条都有「认定理由」，不用懂内部字段
3. **口径说明** 页：告诉对方我们是按什么规则查的

> 💡 「原始流水」和「筛选后标准流水」是给我们内部和核对用的，外行同事不需要看。

## 六、常见问题

### Q1: 运行报错 `FileNotFoundError`？
- 检查 `-i` 后面的文件路径对不对，建议把文件拖进终端自动补全路径。

### Q2: 列名不一样怎么办？
- 方案 A（推荐）：导出数据时改成标准列名
- 方案 B：修改 `cash_shortage/config/specs.py` 里的 `raw_column` 字段，改成你们实际的列名

### Q3: 想加新的检查项？
- 在 `cash_shortage/checks/` 目录下新建一个 `.py` 文件，仿照 `refund_no_sign.py` 的写法
- 在 `checks/auditor.py` 的 `self.checks` 列表里加上你的新函数

### Q4: 想改检查规则？
- 直接改对应文件里的判定逻辑即可，例如想把退款漏签的判定条件放宽，改 `checks/refund_no_sign.py`

### Q5: 运行测试用例？
```bash
python3 tests/test_full_flow.py
```
