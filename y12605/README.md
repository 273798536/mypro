# 儿童几何拼图课堂 - 安全培训审核系统

> 确保每一份审核都有迹可循、有据可依

## 系统特性

### 🔗 数据一致性
- **三级联动**：备注修改 → 评分表标记待同步 → 结论标记待同步
- **可视化状态**：待同步时有黄色闪烁提示，已同步显示绿色标记
- **一键同步**：确认数据无误后点击"标记同步"，状态立即更新
- **导出一致**：导出的 PDF/Excel 文件中同步状态与界面完全一致，避免"页面说通过、文件里又写待确认"

### ⏪ 撤销重做
- **完整历史记录**：每一次操作（添加标注、修改评分、更新备注等）都会被记录
- **快照级回滚**：支持精确回滚到任意历史状态，包括标注位置、评分、备注等所有数据
- **快捷键支持**：工具栏提供撤销/重做按钮，状态灰显时表示无法操作
- **重开机制**：已完成的任务可随时"重开"，状态重置为进行中，历史记录保留

### 🎯 复核流程
- **四关卡设计**：
  1. **基础关卡**：至少2个异常标注
  2. **边界失败关卡**：必须包含一个边界条件失败的标注（如"三角形超出画布边界"）
  3. **撤销重开关卡**：必须执行至少一次撤销操作
  4. **综合结算关卡**：完整审核流程，生成结算报告

### ⚠️ 智能错误处理
- **边界检测**：标注位置超出画布范围时自动检测并给出具体建议
- **缺失素材检测**：自动识别缺少哪些截图素材（如"三角形位置偏移"的错误标注需要截图）
- **可操作建议**：每个错误都给出具体的修复建议，而不是只抛内部错误
- **友好提示**：使用黄色/红色警告框，清晰区分一致性错误和验证错误

### 🏷️ 结果标识系统
训练员拿到结果时，能一眼分清：

| 徽章 | 状态 | 说明 |
|------|------|------|
| 🟢 可直接使用 | `direct_use` | 评分≥70分且结论为通过，无同步问题 |
| 🟠 需培训师复核 | `needs_trainer_review` | 存在待同步数据、或结论为"需确认"、或评分在60-70分之间 |
| 🔴 不可用 | `rejected` | 结论为"不通过" |

### 📤 导出功能
- **PDF 报告**：包含基本信息、审核结论、评分明细、异常标注、待处理问题
- **Excel 表格**：
  - Sheet 1: 审核摘要（含可用性、是否需要复核标记）
  - Sheet 2: 评分表（所有分项评分）
  - Sheet 3: 标注列表（类型、位置、内容）
  - Sheet 4: 操作历史（时间线）
  - Sheet 5: 待处理问题（如有）

- **后端 API**: http://localhost:3001

**重新加载样例数据**：

## 完整操作流程

### 复核演示流程（按用户要求设计）

#### 关卡 1：基础标注
1. 打开任务列表，选择"2026春季班-第3课-创意拼图"（状态：进行中）
2. 在工具栏选择"错误"类型，点击画布任意位置添加一个标注
3. 输入内容："三角形位置正确，拼接紧密" → 点击添加
4. 再添加一个"正确"类型的标注
5. 点击右侧"评分"选项卡，修改几个评分项，注意总分变化

#### 关卡 2：边界失败
1. 从顶部关卡下拉框选择"边界失败关卡"
2. 点击画布靠近边缘的位置（如 x=5, y=5）添加错误标注
3. 输入内容："图形超出画布边界" → 点击添加
4. 系统会自动检测边界越界，显示警告："标注位置(5, 5)超出边界"
5. 查看"待处理问题"区域，会显示具体的边界错误和建议

#### 关卡 3：撤销重做
1. 从顶部关卡下拉框选择"撤销重开关卡"
2. 先添加一个标注，然后点击顶部工具栏的"撤销"按钮（向左箭头）
3. 观察标注消失，历史记录中会有"撤销"操作
4. 点击"重做"按钮（向右箭头），标注恢复
5. 验证当前任务的历史记录中有撤销操作

#### 关卡 4：综合结算
1. 从顶部关卡下拉框选择"综合结算关卡"
2. 点击右侧"备注"选项卡，添加一条备注，勾选"影响评分"和"影响结论"
3. 观察"评分"和"结论"选项卡上出现黄色"待同步"闪烁标记
4. 打开评分选项卡，检查评分是否需要调整，然后点击"标记同步"
5. 打开结论选项卡，填写结论状态、摘要、建议，点击"保存结论"，然后点击"标记同步"
6. 点击顶部"完成审核"按钮
7. 系统自动跳转到结算页面，查看：
   - 顶部醒目的可用性提示（绿色/橙色/红色）
   - 评分环形进度图
   - 标注统计
   - 审核结论
   - 待处理问题列表
8. 点击"导出 PDF"或"导出 Excel"，检查导出内容与界面显示是否一致

## 核心设计决策

### 为什么用 monorepo？
- 前后端共享类型定义，避免重复定义和类型不一致
- 一次安装所有依赖，便于管理
- 代码解耦但关系紧密，符合本项目的架构需求

### 为什么用内存存储？
- 演示用途，无需安装数据库
- 启动速度快，便于从空目录快速运行
- 数据结构清晰，便于理解审核流程
- 如需持久化，可在 `store.ts` 中添加文件写入逻辑

### 撤销重做的实现原理
- 每次操作前保存当前状态快照（snapshot）
- 操作后将快照和新状态存入历史记录
- 撤销时恢复到前一个快照
- 重做时前进到下一个快照
- 如果在历史中间执行新操作，会截断后面的历史

### 数据一致性如何保证？
1. 添加备注时标记"影响评分"/"影响结论"
2. 系统自动将评分表的 `synchronizedWithNotes` 设为 `false`
3. 评分表修改后，系统自动将结论的 `synchronizedWithScoreSheet` 设为 `false`
4. 界面显示"待同步"闪烁标记
5. 用户检查确认后手动点击"标记同步"
6. 完成审核时检查所有同步状态，未同步则不允许完成

## 常见问题

**Q: 为什么服务启动后看不到任务？**
A: 检查后端控制台是否有"已加载 5 条示例任务数据"的输出，如果没有，执行 `npm run seed` 手动加载。

**Q: 导出的文件在哪里？**
A: 导出的文件会自动下载到浏览器的默认下载目录，文件名格式为 `{任务标题}-审核报告.pdf/.xlsx`。

**Q: 如何添加新的关卡？**
A: 在 `packages/shared/src/constants.ts` 的 `REVIEW_LEVELS` 数组中添加新的关卡定义，前后端会自动加载。

**Q: 数据会在重启后丢失吗？**
A: 是的，当前使用内存存储。如需持久化，可以添加 JSON 文件存储或接入数据库。

**Q: 如何修改样例数据？**
A: 编辑 `packages/server/src/seed.ts` 文件中的 `createSampleTask` 函数，然后重启服务或执行 `npm run seed`。
