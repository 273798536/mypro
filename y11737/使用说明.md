# 供应链票据贴现管理系统 - 使用说明

## 一、快速开始

### 1. 启动项目

```bash
# 安装依赖（首次使用）
npm install

# 启动开发服务器
npm run dev
```

启动后访问：http://localhost:5173

### 2. 首次使用

系统首次启动会自动加载 **8 条示例票据数据**，包含各种典型场景：
- ✅ 正常票据（无风险）
- ⚠️ 到期日临近（3天）
- ❌ 贴现率版本错误（使用旧版本）
- 🔗 背书链断裂
- 📅 已过期票据
- ✅ 已审核通过票据

如需恢复初始数据，点击页面右上角「重置示例数据」按钮。

---

## 二、核心功能操作

### 1. 票据列表页

#### 筛选功能
| 筛选项 | 说明 |
|--------|------|
| 票据号码 | 模糊搜索，输入部分号码即可 |
| 申请人 | 模糊搜索公司名称 |
| 风险等级 | 高/中/低风险筛选 |
| 审核状态 | 待审核/已通过/已驳回/已修正 |
| 到期日范围 | 按日期区间筛选 |

点击「重置」按钮清空所有筛选条件。

#### 列表操作
- **行背景色说明**：
  - 🔴 浅红色背景：存在未解决的高风险
  - 🟡 浅黄色背景：存在未解决的中风险
  - ⚪ 白色背景：无风险或风险已解决

- **全选说明**：勾选「全选」时会**自动排除高风险票据**，防止误导出

- **导出功能**：
  - 导出选中：导出勾选的票据
  - 导出全部：导出当前筛选结果中的所有票据
  - 导出格式：Excel (.xlsx)，包含风险标注

### 2. 票据详情页

点击列表「详情」进入详情页。

#### 风险提示区
页面顶部会集中展示所有未解决的风险项：
- 🔴 红色警告：高风险，必须处理后才能审核通过
- 🟡 黄色警告：中风险，建议人工复核
- 可点击「标记已解决」确认风险已处理

#### 基本信息修改
- 点击字段右侧的 ✏️ 图标进入编辑模式
- 修改后点击「保存」，需填写修改原因
- 所有修改会自动记录到「修正历史」

**可修改字段**：票据号码、票面金额、申请人、出票日期、到期日、贴现率、贴现率版本

#### 利息计算
- 自动显示：计息天数、贴现利息、实付金额
- 点击「重新计算」使用最新参数重新计算
- 计算公式：`贴现利息 = 票面金额 × 贴现率 × 计息天数 ÷ 360`

#### 背书链路
- **关系图**：可视化展示背书链条，断裂处显示红色虚线和「断裂!」标识
- **表格**：可点击「修正」修改背书记录，修复断裂链条
- 鼠标悬停节点可查看详细信息

#### 修正历史
时间线展示所有操作记录：
- 修改字段、修改前后值
- 操作人、操作时间
- 修改原因（必填）

#### 审核操作
| 操作 | 条件 | 说明 |
|------|------|------|
| 审核通过 | 无未解决的高风险 | 状态变为「已通过」 |
| 驳回 | 无限制 | 状态变为「已驳回」，需填写原因 |
| 导出 | 无限制 | 导出单条票据详情 |

## 三、风险检测规则

系统自动检测以下风险场景：

### 🔴 高风险（阻断审核通过）

1. **背书链断裂**
   - 检测：前一手被背书人 ≠ 后一手背书人
   - 处理：在背书链路表格中修正对应记录

2. **贴现率版本错误**
   - 检测：使用的版本 ≠ 最新版本（当前最新：v2.1）
   - 处理：修改贴现率版本为最新版

3. **票据号码格式错误**
   - 检测：位数不是 16 位或 30 位，或包含非数字字符
   - 处理：修正票据号码

4. **票据已过期**
   - 检测：到期日 < 当前日期
   - 处理：核实是否为有效票据

5. **利息计算异常**
   - 检测：贴现利息 ≤ 0 或实付金额 ≤ 0
   - 处理：检查票面金额、贴现率、到期日参数

### 🟡 中风险（提示但不阻断）

1. **到期日临近**
   - 检测：距离到期日 ≤ 7 天
   - 建议：优先处理

2. **贴现利息占比过高**
   - 检测：贴现利息 > 票面金额 × 20%
   - 建议：人工复核计算参数

## 四、异常处理路径

### 场景 1：发现背书链断裂

1. 在详情页「风险提示」区看到断裂警告
2. 查看「背书链路」关系图，定位断裂位置（红色节点）
3. 在背书表格中找到对应记录，点击「修正」
4. 修改背书人或被背书人信息，填写修改原因后保存
5. 系统自动重新检测，风险项消失

### 场景 2：贴现率版本错误

1. 在风险提示中看到版本错误警告
2. 在「基本信息」中找到「贴现率版本」字段
3. 点击 ✏️ 编辑，选择最新版本（v2.1）
4. 保存时填写原因，系统自动重新计算利息

### 场景 3：到期日临近

1. 在列表中看到橙色「N天」标签
2. 点击详情核实票据信息
3. 如信息无误，可正常审核通过
4. 如无需贴现，点击「驳回」并填写原因

### 场景 4：数据有误需要恢复

1. 点击列表页右上角「重置示例数据」
2. 确认后所有数据恢复为初始状态
3. **注意**：此操作不可撤销，所有修改会丢失

### 场景 5：导出时提示高风险

1. 选中票据点击「导出选中」
2. 如包含高风险票据，会弹出确认提示
3. 可选择「继续导出」（Excel 中标注风险）
4. 或「取消」后先处理风险再导出

## 五、数据持久化说明

- 所有数据保存在浏览器 **LocalStorage** 中
- 存储 Key：`supply_chain_bills_v1`
- 刷新页面数据不会丢失
- 清除浏览器缓存会导致数据丢失，建议定期导出备份

## 六、技术说明

### 项目结构
```
src/
├── pages/
│   ├── Home.tsx          # 票据列表页
│   └── BillDetail.tsx    # 票据详情页
├── store/
│   └── billStore.ts      # 状态管理（Zustand）
├── services/
│   ├── calculationService.ts  # 利息计算
│   └── riskService.ts         # 风险检测
├── data/
│   └── mockData.ts       # 示例数据
├── types/
│   └── index.ts          # TypeScript 类型定义
└── App.tsx               # 路由配置
```

### 核心计算公式
```
计息天数 = 到期日 - 当前日期
贴现利息 = 票面金额 × 贴现率 × 计息天数 ÷ 360
实付金额 = 票面金额 - 贴现利息
```

## 七、常见问题

**Q: 为什么有些票据无法勾选？**
A: 存在未解决高风险的票据会被自动禁用选择，防止误导出。

**Q: 修改数据后为什么列表没变化？**
A: 所有修改会自动保存并刷新，如未刷新请检查网络或刷新页面。

**Q: 可以导入自己的数据吗？**
A: 目前仅支持示例数据，如需导入请联系开发人员。

**Q: 导出的 Excel 包含哪些字段？**
A: 包含票据全部信息、风险状态、计算结果等 18 个字段，详见导出文件。
