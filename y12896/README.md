# 🌊 潮汐发电闸门演示系统

> 海洋课堂教学演示系统：直观讲解「为什么应该落潮开闸，而不是涨潮开闸」

---

## ⚡ 3 步启动（教师零代码）

### 第 1 步：安装 Node.js（仅首次需要）
- 访问 https://nodejs.org 下载 LTS 版本（推荐 20+）
- 一路下一步安装完成

### 第 2 步：打开终端，进入项目目录
- Mac：打开「终端」，输入 `cd ` 然后把项目文件夹拖进终端，回车
- Windows：打开「命令提示符」，`cd 项目路径`

### 第 3 步：安装依赖并启动
```bash
# 安装依赖（仅首次，约 3-5 分钟）
npm install

# 启动系统（日常使用运行这一条）
npm run dev
```

看到两行提示就启动成功了：
```
Server ready on port 3001        ← 后端 API
➜  Local:   http://localhost:5173/ ← 前端页面，用浏览器打开
```

👉 **用浏览器打开 http://localhost:5173 开始上课**

## 📚 核心教学场景

### ✅ 场景 1：纠正常见误解
1. 打开「策略实验」页
2. 顶部选择「半日潮」+「上海时区」
3. 对比左右两张图：
   - 左侧：**落潮开闸**（正确）→ 高发电量
   - 右侧：**涨潮开闸**（学生常想）→ 发电量仅约 1/10
4. 抛出核心问题：「同样的海水，为什么发电量差这么多？」

### ⚠️ 场景 2：时区错误的坑
1. 在「演示控制台」选择 **混合潮**
2. 时区切换到 **UTC（世界时）** 或 **纽约时区**
3. 观察：时区警告面板出现 + 曲线平移 → 闸门策略完全错位
4. 教学点：潮汐表时间必须对应当地时区！

### 🔧 场景 3：人工故意犯错误
1. 回到「演示控制台」主页面
2. 回放停止在「涨潮」阶段
3. 右下角「闸门人工调整」→ 开闸 100% → 点击应用
4. 观察：高风险告警弹出 + 教学解释 + 发电量影响评估

### 🔥 场景 4：机组保护演示
1. 切换到「全日潮」场景（只有一次发电窗口）
2. 连续播放完整回放
3. 观察：后半段机组温度逐渐升高 → 触发过热保护停机
4. 教学点：保护不是故障，是守护电站安全

## ⚙️ 技术参数（给懂技术的老师）

**内置潮汐场景**
| 场景 | 周期 | 日发电窗口 | 潮差 |
|------|------|-----------|------|
| 半日潮（典型沿海） | 12.42h | 2次 | 2-4m |
| 全日潮（赤道附近） | 24h | 1次 | 1-2m |
| 混合潮（过渡区域） | 双波叠加 | 不规则 | 2-5m |

**物理计算模型**
- 流量：Q = 额定流量 × 开度% × (水头 / 最大水头)
- 功率：P = |Q| × 9.81 × 水头 × 效率 / 1000 （kW）
- 水库水位动态模拟（100万 m² 水库面积）
- 机组温度：满负荷 +2.5℃/30min，冷却 -1.5℃/30min
- 过温保护：≥95℃ 触发停机 3 小时（6 个时间步）

**分级告警系统**
| 级别 | 含义 | 教学处理 |
|------|------|---------|
| 🟦 Info | 提示（蓄水开始/结束） | 正常现象，说明原理 |
| 🟨 Warning | 警告（效率偏低） | 提示改进策略 |
| 🟥 Danger | 严重（涨潮开闸弃水） | 严重错误，立即纠正 |
| ⬛ Shutdown | 停机保护（过温/振动） | 讲解安全设计的重要性 |

## 🛠️ 开发指令（技术人员用）

```bash
# 仅启动前端（默认端口 5173）
npm run client:dev

# 仅启动后端（默认端口 3001）
npm run server:dev

# TypeScript 类型检查
npm run check

# 生产构建
npm run build
```

后端 API 前缀：`/api`
- `GET /api/scenarios` — 场景列表
- `GET /api/scenarios/:id/tides?timezone=xxx` — 潮汐数据（含时区警告）
- `POST /api/calculate` — 计算发电量 `{ scenarioId, strategy: correct|wrong|custom, customGates?, timezone }`
- `POST /api/scenarios/gate-override` — 人工覆写闸门
- `POST /api/report` — 生成课堂报告
- `GET /api/scenarios/:id/protection-records` — 保护停机记录

## 📖 推荐 45 分钟课堂流程

| 时间 | 环节 | 系统操作 |
|------|------|---------|
| 0-5 分钟 | 引入 | 打开「策略实验」→ 展示两种策略发电量差，抛出核心问题 |
| 5-20 分钟 | 原理演示 | 切回「演示控制台」，播放半日潮回放，分段讲解蓄水/发电/待机 |
| 20-30 分钟 | 学生互动 | 让学生故意「涨潮开闸」，观察弃水告警和发电量损失 |
| 30-40 分钟 | 拓展思考 | 切换混合潮 + UTC 时区，展示时区错误如何毁掉整个策略 |
| 40-45 分钟 | 总结 | 打开「课堂报告」→ 导出打印，回顾各时段教学要点 |
