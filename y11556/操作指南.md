# 农资门店配送多源导入巡检工具 - 操作指南

## 一、快速开始

### 1. 环境准备
```bash
# 安装依赖
pip install -r requirements.txt

# 创建样例数据
python create_samples.py
```

```bash
python -m agri_delivery_inspector.cli init
```

## 二、完整工作流程（跟着跑）

### 步骤1：导入数据

#### 导入门店订单
```bash
python -m agri_delivery_inspector.cli import file samples/门店订单_202405.xlsx --type store_order --operator 张经理
```
**预期输出：**
- 批次号：如 `STO-20240524123456`
- 导入结果：成功5条

#### 导入司机轨迹
```bash
python -m agri_delivery_inspector.cli import file samples/司机轨迹_202405.xlsx --type driver_track --operator 张经理
```

#### 导入签收欠条
```bash
python -m agri_delivery_inspector.cli import file samples/签收欠条_202405.xlsx --type sign_receipt --operator 张经理
```

**查看批次列表：**
```bash
python -m agri_delivery_inspector.cli import list
```

---

### 步骤2：数据校验

#### 格式校验（必做）
```bash
python -m agri_delivery_inspector.cli check format <门店订单批次号>
```
**预期发现的问题：**
- 第6行（原始行号）：商品编码为空（样例中第5条数据商品编码故意留空）

#### 重复校验
```bash
python -m agri_delivery_inspector.cli check duplicate <门店订单批次号>
```

#### 交叉校验（核心）
```bash
python -m agri_delivery_inspector.cli check cross
```
**预期发现的问题：**
- ORD20240501002：订单数量30 vs 签收数量25（不一致）
- ORD20240501004：订单金额3800 vs 签收金额3610（不一致）
- 部分订单可能缺少对应数据

#### 赊销替代校验
```bash
python -m agri_delivery_inspector.cli check credit
```

#### 一键全量校验
```bash
python -m agri_delivery_inspector.cli check all --batch <门店订单批次号>
```

**查看所有校验结果：**
```bash
python -m agri_delivery_inspector.cli check list --failed-only
```

---

### 步骤3：问题处理（片区经理重点关注）

#### 场景A：人工改判（系统误报）
假设某条校验结果是误报，需要人工改判：

1. 先找到校验ID：
```bash
python -m agri_delivery_inspector.cli check list --failed-only
```

2. 执行改判：
```bash
python -m agri_delivery_inspector.cli fix override <校验ID> --reason "经核实为正常业务差异" --operator 片区经理王
```

#### 场景B：修正字段值（数据录错）
假设第6行（原始行号）商品编码为空需要修正：

1. 按原始行号查找记录ID：
```bash
python -m agri_delivery_inspector.cli fix find <门店订单批次号> 6
```
**输出：** 记录ID（如 5）

2. 查看记录详情确认：
```bash
python -m agri_delivery_inspector.cli fix record <记录ID>
```

3. 修正字段：
```bash
python -m agri_delivery_inspector.cli fix correct <记录ID> --field product_code --value P005 --reason "补录商品编码，原始单据第5行" --operator 片区经理王
```

#### 场景C：撤回后重导入（整批错误）
```bash
# 撤回批次
python -m agri_delivery_inspector.cli import withdraw <批次号> --reason "原始文件有误，重新导入" --operator 张经理

# 修正Excel后重新导入
python -m agri_delivery_inspector.cli import reimport samples/门店订单_202405_fixed.xlsx --type store_order --original-batch <原批次号> --operator 张经理
```

**查看修正历史：**
```bash
python -m agri_delivery_inspector.cli fix history --batch <批次号>
```

---

### 步骤4：生成巡检报告

```bash
python -m agri_delivery_inspector.cli report
```

**报告重点内容（片区经理看这里）：**
1. **数据汇总**：各数据源记录数、总金额
2. **问题汇总**：按校验类型、严重程度分类统计
3. **失败清单**：带原始行号的错误明细（**最重要**）

---

### 步骤5：导出前冻结 & 导出

#### 冻结批次（确保数据不再变动）
```bash
python -m agri_delivery_inspector.cli export freeze <门店订单批次号> --operator 片区经理王
python -m agri_delivery_inspector.cli export freeze <司机轨迹批次号> --operator 片区经理王
python -m agri_delivery_inspector.cli export freeze <签收欠条批次号> --operator 片区经理王
```

#### 导出失败清单（先给业务整改）
```bash
python -m agri_delivery_inspector.cli export failed --output 失败清单_202405.xlsx
```

#### 导出完整数据（最终交付）
```bash
# 导出所有已冻结批次
python -m agri_delivery_inspector.cli export data --output 配送巡检结果_202405.xlsx
```

**导出文件包含：**
- Sheet1「数据明细」：所有标准化数据，含**原始行号**
- Sheet2「错误清单」：未整改的错误明细

**查看导出历史：**
```bash
python -m agri_delivery_inspector.cli export history
```

## 三、边界情况处理（都已覆盖）

### ✅ 重复提交
- 系统自动检测文件hash，重复文件导入会被拒绝
- 提示已存在的批次号和导入时间

### ✅ 撤回后再提交
- `import withdraw` 标记批次为撤回状态
- `import reimport` 关联原批次号，保留追溯链

### ✅ 部分失败
- 导入时单条失败不影响其他数据
- 失败数据和原因都记录在数据库
- 可单独导出失败清单整改后重导入

### ✅ 人工改判
- 校验结果支持人工改判
- 改判原因和操作人永久记录
- 原始校验结果不删除，保留证据

### ✅ 导出前冻结
- 冻结后批次不可修改
- 未冻结批次不能导出
- 支持解冻（谨慎使用）

## 四、失败路径 & 修正方式对照表

| 失败场景 | 失败路径 | 修正方式 | 报表变化 |
|---------|---------|---------|---------|
| 商品编码为空 | 导入成功→格式校验失败 | `fix correct` 补录编码 | 错误数-1，交叉校验可能新增问题 |
| 订单/签收数量不一致 | 交叉校验失败 | 1. 核实后人工改判<br>2. 修正原始数据重导入 | 不一致项消除或标记改判 |
| 重复导入同一文件 | 导入时直接拒绝 | 无需处理 | 无变化 |
| 整批数据错误 | 导入后发现全错 | `import withdraw` 撤回后重导入 | 原批次数据移出统计 |
| 赊销金额为空 | 赊销校验失败 | `fix correct` 补充金额 | 赊销类错误数-1 |
| 替代商品信息不全 | 赊销校验失败 | `fix correct` 补充替代信息 | 替代类错误数-1 |

## 五、常见问题

### Q: 重启后数据还在吗？
A: 所有数据存在SQLite数据库中（默认路径 `~/.agri-inspect/inspector.db`），重启不丢失。

### Q: 原始证据会不会被覆盖？
A: **绝对不会**。所有操作：
- `raw_data` 表保存原始Excel每一行的完整JSON
- 改判只改 `check_results` 的标记，不删原始错误
- 字段修正只在 `corrections` 表记录变更历史

### Q: 片区经理最需要关注什么？
A: 三个重点：
1. **原始行号**：所有报表、错误清单都带原始Excel行号，方便溯源
2. **失败清单**：`export failed` 导出的Excel可以直接发给业务整改
3. **修正后再导入**：`import reimport` 保留与原批次的关联关系

### Q: 回款对不上的结论怎么出才不漂？
A: 必须走完整流程：
1. 四单（订单、轨迹、签收、二次确认）全部导入
2. 交叉校验所有不一致项
3. 每个差异项要么修正数据、要么人工改判附原因
4. 所有批次冻结后导出
5. 报告附带改判说明和修正历史

| 命令组 | 子命令 | 功能 |

| | reimport | 重导入（关联原批次） |

| | list | 列出批次 |

| | format | 格式校验 |
| | duplicate | 重复校验 |
| | cross | 交叉校验 |
| | credit | 赊销替代校验 |
| | list | 列出校验结果 |
| **fix** | override | 人工改判 |
| | correct | 修正字段 |
| | record | 查看记录详情 |
| | find | 按行号找记录 |
| | history | 修正历史 |
| **report** | - | 生成巡检报告 |
| **history** | - | 导入历史 |
| **export** | freeze | 冻结批次 |
| | unfreeze | 解冻批次 |
