## 三、智能备注匹配规则（不用记，写对关键词就行）

备注内容里含以下关键词，系统会自动关联对应材料：

| 匹配维度 | 命中条件 | 示例 |
|---------|---------|------|
| 备注类型 `--type rehearsal` | 含"排练"的文件或 `SCREENSHOT` 类型 | 自动关联所有 `排练群截图_*.txt` |
| 备注类型 `--type auth` | 含"授权"的文件或 `AUTH_DOC` 类型 | 自动关联 `授权文件_耳返设备.txt` |
| 学生名关键词 | 备注里有"学生A/学生B/学生C/甲乙丙" | "学生A进步" → 关联所有提到学生A的材料 |
| 文件名关键词 | 备注里有"分账/奖励/附件/结论/截图" | "分账结论已确认" → 关联 `分账结论_最终版.txt` |

> 如果智能匹配没匹配上，输出会提示：
> ```
> ⚠️  未关联任何材料。备注仅会出现在历史备注区。
>    建议用 --material 指定，或备注内容含关键词（如 学生A、授权、排练、分账）。
> ```

## 四、已知风险与手动补救

### ⚠️ 4.1 状态-报告不一致怎么办？

**现象**：`status` 显示材料0、备注0，但 `reports/` 里的报告还显示5份材料。

**原因**：中间跑过 `reset` 或者手动删了 `data/`，但旧报告没清。

**解决**：
```bash
rm -rf data reports delivery   # 全清
python3 -m src.cli scan ./materials  # 重新扫
```

**预防**：每次 reset 或删 data 后，也把 reports 和 delivery 一起删掉。

---

### ⚠️ 4.2 学生进步分析依赖关键词匹配

当前使用**句子级关键词匹配**（必须在同一行同时出现"学生名 + 技巧 + 进步词"）：

- **可能漏报**：技巧和进步在不同行（如"学生A的高音。比上周好多了"）会被漏掉
- **可能误报**：反讽句（如"学生A的高音进步了？并没有"）仍会被识别为进步
- **仅支持中文名**：目前关键词只覆盖"高音、节奏、音准、气息、咬字、发声、低音"

**手动补救方式**：直接在备注里描述清楚，备注会出现在学生进步报告的"相关备注"区。

---

### ⚠️ 4.3 授权到期检测依赖正则表达式

仅能识别以下格式（出现在文件内容或备注里）：
```
到期日：2026-07-15
有效期至 2026/07/15
expire: 2026-07-15
```

- **不支持**："七月十五日"、"下月底"、"一个季度后"等非标准日期描述
- **多个日期**：会取备注/文件内容里最后出现的合法日期

**手动补救**：用 `note --type auth "到期日：2026-07-20"` 明确写一条。

---

### ⚠️ 4.4 晚到附件判定依赖文件接收时间

- 判定方式：按 `received_at` 或文件系统 `mtime` 排序，最后到达的 `附件` 类型 + 比结论晚 → 标记为晚到
- **风险**：如果文件复制/打包导致时间戳被修改，可能会误判或漏判
- **手动补救**：在备注里明确说明"这是晚到的附件"

---

### ⚠️ 4.5 版本追踪按内容哈希判断

- 重扫时，如果文件内容 MD5 变化 → 版本号 +1
- **小修改也会加版本**：标点、空格、换行变化同样触发
- 只追踪**内容变化**，不追踪是谁/什么时间改的

---

### ⚠️ 4.6 重启后状态恢复

- 所有数据存在 `data/state.json` 里（UTF-8 JSON）
- 如果 `state.json` 被**误删**或**手动改坏**：
  - 所有历史备注会丢失 ❌
  - 可以通过重新 scan 重新获得材料，但备注需重加
  - **建议**：重要阶段备份 `data/state.json`
  - 备份命令：`cp data/state.json data/state.json.backup.$(date +%Y%m%d)`

---

### ⚠️ 4.7 智能匹配的边界情况

- 如果两个材料都提到"学生A"，备注会同时关联到这两个材料（可能多关联，但不会漏）
- 如果完全匹配不上，不会强行关联（避免错关联），会提示人工用 `--material` 指
