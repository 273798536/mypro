# 巡演耳返分账对齐 - 材料处理系统

音乐老师林姐专用：把排练群里零散的材料串成一条完整的处理链，让老师一眼就能看到学生哪里进步了。

---

## 一、快速开始（林姐请按这个顺序跑）

> **注意**：以下命令请在项目根目录下运行。`python` → macOS 请用 `python3`。

### 第 1 步：清理旧状态（可选，第一次跑或者想重来时）

```bash
rm -rf data reports delivery
```

### 第 2 步：扫描材料

```bash
python3 -m src.cli scan ./materials
```

扫描 `materials/` 目录下所有文件，系统会自动：
- 识别材料类型（排练截图 / 附件 / 授权文件 / 结论）
- 检测授权到期日并标⚠️
- 把晚到附件自动关联到最终结论
- 按句子级分析学生进步
- 生成 **第1版** 两份 Markdown 报告

### 第 3 步：看一下当前状态

```bash
python3 -m src.cli status
```

检查处理状态，特别关注：
```
对齐率: xx% (x/5)   ← 一开始是 0.0%，补完备注就会涨
已对齐: xx 份        ← 目标是 5/5
对齐问题:            ← 提示哪些材料还缺人工批注
```

### 第 4 步：补人工批注（核心一步！）

> **重要**：备注里只要出现关键词，系统会**自动关联**对应材料，不用手动加 `--material`。

| 想备注什么 | 命令示例 | 自动匹配到的材料 |
|-----------|---------|----------------|
| 排练观察（含学生名） | `python3 -m src.cli note --type rehearsal "学生A的高音稳多了，节奏也进步"` | 所有排练截图 + 含学生A的材料 |
| 授权到期日 | `python3 -m src.cli note --type auth "授权到期确认到2026-07-20，双方已确认"` | 授权文件_耳返设备.txt |
| 分账/附件/奖励 | `python3 -m src.cli note "学生A的额外奖励，分账结论暂未包含"` | 分账结论 + 补充附件 |

运行后看输出中这一行，确认关联了哪些材料：
```
关联材料（智能匹配）: 排练群截图_20260610.txt, 排练群截图_20260612.txt
```

> 如果想手动指定材料ID，用 `--material` 参数重复多次即可。

### 第 5 步：重扫（每次补完备注后都要跑）

```bash
python3 -m src.cli scan ./materials --rescan
```

- 检测内容变化 → 自动加版本号 v1→v2
- 更新对齐状态（对齐率会涨）
- 重新生成两份 Markdown 报告（**包含最新备注**）

### 第 6 步：查看报告

**重点看这份（林姐最关心）**：
```bash
cat reports/学生进步分析.md
```

**查分账、授权、对齐状态看这份**：
```bash
cat reports/分账对齐报告.md
```

也可以用这个命令查看处理概览：
```bash
python3 -m src.cli review
python3 -m src.cli review --filter-auth    # 只看带授权标记的
python3 -m src.cli review --filter-late    # 只看晚到附件
python3 -m src.cli review --detail <材料ID>  # 某份材料的详情
```

### 第 7 步：导出交付（要发给别人时）

```bash
python3 -m src.cli export ./delivery
```

生成完整的现场材料包在 `delivery/` 目录：
```
delivery/
├── materials/          # 所有原件，带 ⚠️/[晚到]/[结论] 标记
├── 交付清单.md         # 最终交接用的清单表格（含版本、备注数）
├── 分账对齐报告.md     # 完整分账报告
├── 学生进步分析.md     # 学生进步明细
├── 历史备注.md         # 所有人工批注归档
└── 状态摘要.json       # 机器可读的处理状态
```

## 二、核心检查点（每次跑完确认这几条）

| # | 检查什么 | 怎么确认 | 通过标准 |
|---|---------|---------|---------|
| 1 | 对齐率是不是真的涨了 | `status` 命令里的 `对齐率` | 添加 N 条备注后，对齐率 = 已关联材料数 / 5 |
| 2 | 备注真的落到材料上了 | 看 `分账对齐报告.md` 第2节表格里的"备注数"列 | 每份关联过的材料备注数 ≥ 1 |
| 3 | 学生进步点不重复 | 打开 `学生进步分析.md` | 每个学生每个技巧+进步词只出现1次（如"高音进步"不重复） |
| 4 | 进步点有证据 | 学生进步报告里的"证据原文"段落 | 每条进步点能在下面看到 1-N 条原文引用 |
| 5 | 授权标记贯穿全链路 | 报告+材料导出文件名 | 授权文件应带 ⚠️，报告第3节，交付清单表格 |
| 6 | 晚到附件真连上结论 | `分账对齐报告.md` 第4节 | 补充附件 ↔ 分账结论 双向关联 |
| 7 | 重启不丢数据 | 再跑一次 `status` 或重新scan | 数据应完全一致（持久化在 `data/state.json`） |
| 8 | 交付材料带标记 | 看 `delivery/materials/` 文件名 | 授权有 ⚠️，补充附件带[晚到]，结论带[结论] |

## 三、智能备注匹配规则（不用记，写对关键词就行）

备注内容里含以下关键词，系统会自动关联对应材料：

| 匹配维度 | 命中条件 | 示例 |
|---------|---------|------|
| 备注类型 `--type rehearsal` | 含"排练"的文件或 `SCREENSHOT` 类型 | 排练群截图_*.txt |
| 备注类型 `--type auth` | 含"授权"的文件或 `AUTH_DOC` 类型 | 授权文件_耳返设备.txt |
| 学生名关键词 | 备注里有"学生A/学生B/学生C/甲乙丙" | "学生A进步" → 关联所有提到学生A的材料 |
| 文件名关键词 | 备注里有"分账/奖励/附件/结论/截图" | "分账结论已确认" → 关联分账结论_最终版.txt |

> 如果智能匹配没匹配上，输出会提示：
> ```
> ⚠️  未关联任何材料。备注仅会出现在历史备注区。
>    建议用 --material 指定，或备注内容含关键词（如 学生A、授权、排练、分账）。
> ```

## 四、已知风险与限制

### ⚠️ 4.1 学生进步分析依赖关键词匹配

当前使用**句子级关键词匹配**（必须在同一行同时出现"学生名 + 技巧 + 进步词"）：

- **可能漏报**：技巧和进步在不同行（如"学生A的高音。比上周好多了"）会被漏掉
- **可能误报**：反讽句（如"学生A的高音进步了？并没有"）仍会被识别为进步
- **仅支持中文名**：目前关键词只覆盖"高音、节奏、音准、气息、咬字、发声、低音"

**手动补救方式**：直接在备注里描述清楚，备注会出现在学生进步报告的"相关备注"区。

### ⚠️ 4.2 授权到期检测依赖正则表达式

仅能识别以下格式（出现在文件内容或备注里）：
```
到期日：2026-07-15
有效期至 2026/07/15
expire: 2026-07-15
```

- **不支持**："七月十五日"、"下月底"、"一个季度后"等非标准日期描述
- **多个日期**：会取备注/文件内容里最后出现的合法日期

### ⚠️ 4.3 晚到附件判定依赖文件接收时间

- 判定方式：按 `received_at` 或文件系统 `mtime` 排序，最后到达的 `附件` 类型 + 比结论晚 → 标记为晚到
- **风险**：如果文件复制/打包导致时间戳被修改，可能会误判或漏判
- **手动补救**：在备注里明确说明"这是晚到的附件"

### ⚠️ 4.4 版本追踪按内容哈希判断

- 重扫时，如果文件内容 MD5 变化 → 版本号 +1
- **小修改也会加版本**：标点、空格、换行变化同样触发
- 只追踪**内容变化**，不追踪是谁/什么时间改的

### ⚠️ 4.5 重启后状态恢复

- 所有数据存在 `data/state.json` 里（UTF-8 JSON）
- 如果 `state.json` 被**误删**或**手动改坏**：
  - 所有历史备注会丢失 ❌
  - 可以通过重新 scan 重新获得材料，但备注需重加
  - **建议**：重要阶段备份 `data/state.json`

### ⚠️ 4.6 智能匹配的边界情况

- 如果两个材料都提到"学生A"，备注会同时关联到这两个材料（可能多关联，但不会漏）
- 如果完全匹配不上，不会强行关联（避免错关联），会提示人工用 `--material` 指
