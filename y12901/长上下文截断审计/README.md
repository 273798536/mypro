# 长上下文截断审计工具

用于审计和分析长文本截断情况的命令行工具。适合平台工程师做长上下文截断审计复核，
导出的报告即使不懂代码也能看懂。

## 快速开始

### 1. 安装依赖

```bash
cd 长上下文截断审计
pip install -r requirements.txt
```

### 2. 运行样例（推荐先跑这个）

```bash
python audit_tool.py demo
```

会自动用 `samples/` 目录里的样例数据跑一遍，生成的报告在 `demo_output/` 目录里。

## 常用命令

### 审计单个文件

```bash
python audit_tool.py audit -i 数据文件.csv -o 输出报告.xlsx
```

参数说明：

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--input` / `-i` | 是 | - | 输入数据文件，支持 CSV 和 Excel |
| `--output` / `-o` | 否 | `audit_result.xlsx` | 输出文件路径，`.xlsx` 或 `.html` |
| `--max-tokens` | 否 | `4096` | Token 数量限制，超过算截断 |
| `--context-window` | 否 | `8192` | 上下文窗口大小，接近就警告 |
| `--source-name` | 否 | `""` | 给这批数据标记来源 |
| `--with-explanation` | 否 | `开启` | Excel 里带不带名词说明页 |

### 合并旧表 + 人工反馈（带版本追踪）

```bash
python audit_tool.py merge \
  --old-data 旧表.csv \
  --new-data 人工反馈.csv \
  -o 合并结果.xlsx
```

这个命令会：
- 把两份数据按记录编号合并
- 保留每个记录的版本历史
- 人工修正过的判断会显示前后差别
- 生成版本对比报告

## 输入文件格式

CSV 或 Excel 文件，至少要有一列叫 `原始内容`。

推荐包含的列：

| 列名 | 说明 |
|------|------|
| 记录编号 | 每条数据的唯一标识，合并时用这个匹配 |
| 原始内容 | 要检查的文本内容 |
| 截断内容 | （可选）截断后的内容，用来对比 |
| 来源 | （可选）数据来源，比如"旧表"、"群反馈" |
| 人工备注 | （可选）人工标注的备注 |
| 修正判断 | （可选）人工复核后的判断，比如"不截断" |

## 样例数据说明

`samples/` 目录里的样例数据模拟了真实场景：

- `old_records.csv` - 旧表数据，包含各种情况
  - 正常完整的记录
  - 内容超长的记录
  - 文档没写完的（突然结尾）
  - 漏填单位的（"5万条左右"这种不明确的）
  - 空数据和只有空格的坏数据
  - 带人工备注的

- `manual_feedback.csv` - 群里补的人工反馈
  - 修正了之前的错误判断
  - 补充了新的记录
  - 包含工具调用参数错误的情况

- `edge_cases.json` - 工具调用参数错误的边界案例（3个真实改变结果的）
  - 参数类型错误（数字当字符串传）
  - 必传参数遗漏
  - 参数值超出有效范围

## 输出报告内容

### Excel 报告（推荐转给非技术人员）

1. **审计总览** - 统计数据、截断率、按原因分布
2. **详细记录** - 每条数据的审计结果，支持筛选排序
3. **名词说明** - 用大白话解释专业术语

### 版本对比 Excel

- 人工修正过的记录逐条对比
- 显示修正前和修正后的值
- 核心判断改变的会标红突出

### HTML 报告

- 网页版，直接浏览器打开
- 可视化的原因分布条形图
- 标签化展示，更直观
- 包含人工修正记录对比

## 常见问题

**Q: 我不懂代码能用吗？**
A: 可以。装好依赖后，把数据整理成 CSV，运行 `audit` 命令就行。
报告里有名词说明页，专业术语都有大白话解释。

**Q: 工具调用参数错误算截断吗？**
A: 算的。因为参数错了导致工具返回空或者异常，效果等同于内容被截断了。
样例里有 3 个常见的参数错误案例，都是真的会改变结果的。

**Q: 人工修正后怎么看差别？**
A: 用 `merge` 命令合并旧表和人工反馈，会生成版本对比报告，
每条修正过的记录都能看到改了什么、改之前是什么样。
