# 声学混响参数回放工具

> 老唐，这是给你用的。不用看代码，不用先装任何东西，按下面两步走就行。

---

## 你需要做的两步（就两步，零依赖开箱即用）

### 第一步：准备材料包

打开终端，进入本项目目录，**直接跑这条命令**（不需要 `npm install`）：

```bash
npm run prepare-materials
```

跑完会在 `data/input/` 目录里生成以下材料（就像现场会收到的那包东西）：

| 文件 | 是什么 | 你需要关心的 |
|------|--------|-------------|
| `normal_record_REC-20260612-001.json` | 一条正常的混响参数记录 | 6月12日上午9点半3号场地的正常校准数据 |
| `repair_note_REP-20260611-003.json` | 维修备注 | 6月11日换了3号场地主音箱的高频单元 |
| `gap_record_REC-20260612-002.json` | 带采样缺口的记录 | 6月12日下午3点复测，中间有些频段数据没采到 |
| `supplementary_note_SUP-20260612-001.json` | 后补说明 | 老唐你自己写的那段补充说明，说等厂家6月16日来调 |
| `manifest.json` | 材料清单 | 列清楚了这包里都有啥 |

### 第二步：跑回放，然后看异常队列

材料准备好以后，跑这条命令：

```bash
npm run playback:demo
```

（如果是你自己准备的真实材料，用 `npm run playback`，遇到采样缺口会停下来问你要不要挂起。）

跑完会在 `data/output/` 目录生成下面这些文件：

| 文件 | 你先看哪个 | 里面有什么 |
|------|-----------|-----------|
| **`异常队列_阅读版.txt`** | **第一个看这个** | 人能直接读的异常和缺口清单，写得明明白白 |
| `anomaly_queue.json` | 第二个看（如果第一个不够） | 和阅读版内容一致，给系统/页面用的，状态说法一样 |
| `terminal_summary.txt` | 第三个看 | 终端上显示的摘要，存档用 |
| `playback_report.json` | 需要追溯数字时再看 | 每个参数值从哪来的线索都在这里 |

---

## 遇上采样缺口怎么办？

工具检测到数据缺失（比如500Hz、2kHz频段没采到），会：

1. **自动挂起**，不强行给出"稳定"的假结论
2. 把这条挂起记录写进 **异常队列_阅读版.txt**，状态标成 `已挂起-待补测确认`
3. 你（或负责人）确认补测计划，补完数据后再重新跑第二步

> 记住：宁可挂起等人确认，也别给假稳定结论。

## 评审会要讲给不懂代码的人听？数字从哪来怎么说？

打开 `data/output/playback_report.json`，每个参数都带着这些线索：

```
参数值 1.08 (以RT60-1kHz为例)
├── 来自哪条记录: REC-20260612-001
├── 参数版本: v2.3.1
├── 谁测的: 老唐
├── 什么时候测的: 2026-06-12 09:30
├── 在哪测的: 训练馆A区-3号场地
├── 用什么测的: Shure SM58话筒 + JBL EON615音箱 + NTi XL2分析仪
└── 原始数据在哪: measurement_log_20260612_0930.xlsx，Sheet1，B12到B28行
```

评审会上有人问"这个1.08怎么来的"，照着上面念就行。

## 异常队列，页面上看的和文件里说的要一致

`anomaly_queue.json`（页面用）和 `异常队列_阅读版.txt`（人看的）是一起生成的，内容和状态对应关系：

| JSON里的 status | JSON里的 displayStatus | 阅读版里显示的状态 |
|-----------------|----------------------|-------------------|
| `pending` | `异常待处理` | 状态: 异常待处理 |
| `suspended` | `已挂起-待补测确认` | 状态: 已挂起-待补测确认 |
| 整体 `pending_review` | 整体 `待负责人确认` | 顶部: 当前状态: 待负责人确认 |

两处说法完全一致，不会出现页面说"已处理"但文件里还写"待处理"的情况。

## 完整命令速查

```bash
# 1. 生成示例材料包（就像现场收到的一包）
npm run prepare-materials

# 2. 跑回放（交互模式，遇缺口会问你要不要挂起）
npm run playback

# 3. 跑回放（非交互模式，遇缺口自动挂起，不问）
npm run playback:demo
```

自定义输入输出目录：

```bash
node src/cli.js playback -i /你的材料目录 -o /你想放结果的目录
node src/cli.js prepare -o /你想放材料的目录
```
