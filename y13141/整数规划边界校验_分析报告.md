## 二、异常点（同页展示）

### 异常点1：单位不一致导致灵敏度假稳定

| 项目 | 正确路径（统一吨） | 错误路径（混入kg未换算） |
|------|-------------------|------------------------|
| 原材料B约束 | a₂₁x₁ + a₂₂x₂ ≤ b₂（吨） | 误将b₂当作2500kg，但a仍用吨系数 |
| 当前解检验 | 0.12×12 + 0.12×8 = 2.4吨 ≤ 2.5吨 ✓ | 0.12×12 + 0.12×8 = 2.4 ≤ 2500 ✓ |
| 约束都满足？ | 是 | 是（假通过） |
| 上界+5%扰动 | 2.5×1.05 = 2.625吨 | 2500×1.05 = 2625（单位混乱） |
| 扰动后2.4 ≤ 上界？ | 2.4 ≤ 2.625 ✓ 仍可行 | 2.4 ≤ 2625 ✓ 仍可行 |
| 下界-5%扰动 | 2.5×0.95 = 2.375吨 | 2500×0.95 = 2375（单位混乱） |
| 扰动后2.4 ≤ 上界？ | **2.4 ≤ 2.375 ✗ 触发边界，最优解变化** | 2.4 ≤ 2375 ✓ **假稳定，最优解不变** |

> **异常定位**：样本REC-2026-0613-0042单独看完全正常，但其原材料B单位为"吨"，同批次其余样本为"kg"，混入后触发灵敏度判断错误。

### 异常点2：整数取整边界

| 项目 | 值 |

## 三、解释与结论（同页展示）

### 3.1 为什么一条"正常记录"影响结论

样本REC-2026-0613-0042本身各项指标均合规：
- x₁=12、x₂=8均为整数，满足取值范围
- 原材料A消耗2400kg ≤ 2500kg
- 原材料B消耗2.4吨 ≤ 2.5吨
- 目标函数值15680元

**但它是"单位孤岛"**：同批次其他37条样本的原材料B均以"kg"为单位录入（如2400kg、2350kg等），唯独该样本以"吨"录入（2.4吨）。在批量校验脚本未做单位统一的情况下：
- 单独校验：脚本按样本内单位自洽，通过
- 批次汇总：该样本的2.4被当作"2.4kg"参与统计和灵敏度分析
- 结果：IP-006灵敏度分析得出"参数±5%扰动下最优解稳定"的**假结论**

### 3.2 处理结果

1. **当前批次状态**：挂起
2. **挂起原因**：存在单位不一致样本，且触发IP-007重复样本判定（同一输入参数存在吨/kg两种版本）
3. **已通知**：项目经理（2026-06-13 10:15邮件）
4. **建议**：确认该样本是录入错误（应为2400kg）还是特殊场景（确实以吨为单位），确认后再放行
