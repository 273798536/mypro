# 节奏维修工 - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品定位
"节奏维修工"是一款面向音乐教学的节奏训练游戏，通过维修机器的互动方式帮助学生理解节拍概念，解决学生练节拍靠听感猜的问题。

### 1.2 目标用户
- 音乐学习者（学生）
- 音乐教师（用于教学辅助）

### 1.3 核心价值
- **可视化教学**：将抽象的节拍概念转化为具象的机器维修操作
- **错误可追溯**：每次错误都有明确的原因说明，而非单纯扣分
- **脏数据兼容**：支持处理不规范的节拍数据，避免整批失败
- **动态难度**：玩家选择真实影响游戏局面和最终报告

## 2. 功能需求

### 2.1 游戏核心玩法

#### 2.1.1 节拍轨道系统
- 多条轨道对应不同节拍类型（四分音符、八分音符、切分音等）
- 音符从轨道上方下落，到达判定线时点击
- 支持速度变化（渐快/渐慢）
- **脏数据处理**：
  - 空值音符：自动跳过并记录到待确认区
  - 备注信息：保留显示但不影响判定
  - 格式错误：尝试解析，失败则标记为待确认

#### 2.1.2 机器维修机制
- 背景为待维修的工业机器
- 正确点击：修复对应部件，机器运转更顺畅
- 错误点击：部件故障加重，产生火花/震动效果
- 连击：机器进入超频模式，视觉效果增强
- 漏拍：关键部件停转，发出警报音

### 2.2 节奏判定系统

#### 2.2.1 判定等级
| 判定 | 时间窗口 | 效果 |
|------|----------|------|
| PERFECT | ±50ms | 完美修复，+100分 |
| GREAT | ±100ms | 良好修复，+80分 |
| GOOD | ±150ms | 勉强修复，+50分 |
| MISS | >±150ms | 维修失败，0分 |

#### 2.2.2 错因分析
- **早按**：点击时间早于判定窗口
- **晚按**：点击时间晚于判定窗口
- **漏拍**：未在音符生命周期内点击
- **切分音漏拍**：切分音位置错误（高亮标记）
- **速度误判**：速度变化区间判定错误（标记为待确认）
- **连击误判**：连击中断（标记为待确认）

### 2.3 待确认区

#### 2.3.1 功能
- 实时显示可疑判定
- 包括：速度变化判定、连击误判、脏数据
- 玩家可点击标记确认/驳回
- 影响最终结算报告

#### 2.3.2 显示内容
- 可疑判定时间点
- 原始数据（含备注）
- 系统判定结果
- 确认/驳回按钮

### 2.4 结算报告

#### 2.4.1 基础统计
- 总分
- 各判定等级数量
- 连击数（最高/当前）
- 准确率

#### 2.4.2 错因统计
- 按错因分类统计（早按/晚按/漏拍等）
- 切分音错误率
- 速度变化适应度
- 脏数据处理统计

#### 2.4.3 可视化
- 节拍偏差时间轴
- 错误位置热力图
- 机器维修完成度展示

## 3. 界面设计

### 3.1 主界面
- **顶部**：分数、连击数、机器健康度
- **中部**：节拍轨道区域（4条轨道）
- **左侧**：待确认区（可展开/收起）
- **底部**：速度指示、进度条

### 3.2 结算界面
- 大标题：维修完成报告
- 左侧：统计数据面板
- 右侧：错误分析可视化
- 底部：重新开始/导出报告按钮

### 3.3 视觉风格
- **主题**：工业机械风 + 蒸汽朋克元素
- **主色调**：深灰、铜色、机械蓝
- **动效**：齿轮转动、蒸汽喷出、电流火花
- **字体**：等宽机械字体 + 装饰性标题字体

## 4. 数据规范

### 4.1 输入数据格式
```json
{
  "bpm": 120,
  "speedCurve": [
    { "time": 0, "bpm": 120 },
    { "time": 30, "bpm": 140 }
  ],
  "notes": [
    {
      "time": 1.0,
      "track": 0,
      "type": "quarter",
      "remark": "重点练习"
    },
    {
      "time": 1.5,
      "track": 1,
      "type": "eighth",
      "remark": null
    },
    {
      "time": 2.0,
      "track": null,
      "type": "syncopated",
      "remark": "脏数据示例"
    }
  ]
}
```

### 4.2 脏数据处理规则
1. **null/undefined**：跳过，记录到待确认区
2. **空字符串**：视为有效空值，不处理
3. **格式错误**：尝试容错解析，失败则标记
4. **备注信息**：全部保留显示

## 5. 验收标准

- [ ] 游戏可正常启动和游玩
- [ ] 节拍判定准确（±10ms误差内）
- [ ] 脏数据不导致游戏崩溃
- [ ] 待确认区功能完整
- [ ] 结算报告包含所有错因分析
- [ ] 玩家选择影响最终报告内容
