# 最短路径错题复盘 · 白话说明

_生成于 2026-06-12 21:50:08_

## 这是什么

我们把教研编辑阿宁手上的「最短路径错题」包了一次电子体检, 下面用大白话讲清楚数字从哪来、问题出在哪.

## 数字怎么来的 (线索)

- 我们拿了 **5 份样例文件** (sample01_basic_ok.csv, sample02_wrong_distance.csv, sample03_sort_unstable.csv, sample04_empty_set.csv, sample05_dirty_draft.csv)
- 每份文件里每一行对应一道题的一条边, 总共 **30 行**
- 每行都带着: 学生写的答案(`student_answer`)、参考正确答案(`expected_answer`)、原始草稿页码(`origin_draft`)、老师标过的来源行号(`source_line`)
- 所有数字都可以对照 `samples/` 目录里的原文件, 原始草稿字段我们一个字都没改.

## 结果怎么读

- **7 行** 学生答案对得上 → 绿勾
- **12 行** 学生把某个节点的距离算错了 → 红叉, 可在 `origin_draft` 里找到对应草稿页
- **6 行** 距离没错但顺序摆错了 (同距离的节点谁在前谁在后不一致)
  - 具体卡在哪:
    - 在 sample03_sort_unstable.csv 里, 距离=5 的节点 ['B', 'E'], 第 1 位学生先写了 **B**, 但应该先写 **E** (可查来源行 21, 22, 23 等)
- **5 行** 学生交了空答案 → 空集合千万别当成正常输入放过去 (阿宁的痛点)
- **0 行** 学生草稿上乱写 (比如 `INF`/`??`/`?`) → 我们**保留原稿没洗**, 方便教研看原始笔迹

## 数字要追查怎么办

1. 打开 `samples/` 下对应文件名
2. 看 `source_line` 列 → 回到老师原来标的行号
3. 看 `origin_draft` 列 → 回到学生手写草稿的页码
4. 再不信 → 看 `store/state.json` 里 `runs[].fingerprint` 做文件指纹比对
