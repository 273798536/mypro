# 客服摘要灰度对比

新旧模型对比工具，用于灰度发布前的效果验证。

## 快速开始

### 步骤 1：准备数据

将新旧模型预测结果放入 `data/` 目录：
- `old_model.json` - 旧模型预测结果
- `new_model.json` - 新模型预测结果
- `version_notes.json` - 版本说明（可选）
- `withdrawals.json` - 撤回记录（可选）
- `supplementary.json` - 后补说明（可选）

### 步骤 2：运行对比

```bash
python run_gray_compare.py
```

### 步骤 3：查看报告

生成的报告位于 `output/gray_comparison_report.md`，可直接发给现场老师。

## 坏材料处理指南

### 遇到以下情况时，请先看这里：

| 现象 | 查看位置 | 处理方式 |
|------|----------|----------|
| 指标涨了但不知道样本有没有变 | 报告「一、对比概览」→ 待补材料/待确认数量 | 检查 `data/` 目录是否缺少 `version_notes.json` |
| 版本说明出现重复评测 | 报告「⚠️ 待确认事项」章节 | 先确认重复原因和影响范围，标记确认后重新跑 |
| 收尾时冒出新问题 | 报告末尾「四、样本详情」→ 待补材料/人工改判 | 检查 `withdrawals.json` 和 `supplementary.json` |
| 旧模型误判样本新模型仍错 | 报告「二、误判样本回测分析」→ ❌标记样本 | 查看 `sample.revision_explanation` 定位问题 |
| 阈值变化导致结论反转 | 报告「一、对比概览」→ 受阈值影响数量 | 运行 `python run_threshold_test.py` 测试不同阈值 |

### 常见问题

1. **Q: 材料断断续续怎么办？**
   A: 少量版本说明、撤回记录、后补说明也能跑，系统会像处理真实材料一样处理。

2. **Q: 重复评测要不要急着算完？**
   A: 不要。系统会先给出「待确认原因」和「影响范围」，人工确认后再继续。

3. **Q: 人工改判能盖过模型吗？**
   A: 会。`respect_manual=True` 时人工判断优先级最高，阈值变化不会覆盖人工结论。

4. **Q: 误判样本放回后怎么看改判原因？**
   A: 回测样本的 `revision_explanation` 字段会给出详细改判解释，包括得分变化、特征变化、阈值调整等。
