# 分段回归批量验算

投研复核人专用：导参数表 → 看图找异常 → 一路下钻回原始材料 → 标注复核状态。

## 快速开始（3 步）

### 1. 启动后端

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

后端 API 文档：http://localhost:8000/docs

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev
```

打开 http://localhost:5173

### 3. 上传参数表并复核

1. 点「上传参数表」，选 Excel/CSV，填版本号，点导入
2. 在列表页点「复核」进入总览页
3. 看散点图，点红色异常星标 → 看原始材料 → 标状态（已处理 / 待补材料 / 人工改判）

## 坏材料来了看哪里

收到参数表先别跑回归，按这个顺序查：

| 问题 | 看哪里 | 说明 |
|------|--------|------|
| 列名对不上 | 上传成功页 → 字段匹配详情 | 系统会模糊匹配，置信度低的会标红 |
| 单位缺失 | 复核总览页 → 异常点 → 查看原始材料 | 单位来源会写清楚是从哪个原始字段读的，还是推测的 |
| 权重被改过没人认 | 复核总览页 → 参数版本 & 变更日志 | 所有字段修改都有修改人、修改时间、改前值、改后值、原因 |
| 异常点太多 | 复核总览页 → 异常点列表 → 筛选「待补材料」 | 先把需要补材料的挑出来，别全堆着 |
| 只剩结论没过程 | 复核总览页本身 | 同页有：图表 + 参数版本 + 异常点 + 变更日志 + 字段匹配 |
| 复核状态混在一起 | 复核总览页 → 复核状态统计 / 异常点 Tab 筛选 | 三种状态分开：已处理 / 待补材料 / 人工改判 |

## 核心概念

- **参数表 (ParameterSheet)**：一次上传的 Excel/CSV，带版本号
- **分段回归 (Piecewise Regression)**：按断点把 X 轴切成多段，每段独立做线性回归
- **异常点 (AnomalyPoint)**：残差 Z 分数超阈值的点，初始状态=待补材料
- **复核三状态**：
  - `processed` 已处理 —— 正常，确认过了
  - `pending_material` 待补材料 —— 有问题，需要找来源补材料
  - `manual_overrule` 人工改判 —— 有问题但人工确认保留

## 数据留痕

- 字段名不一致：`column_mapping` 记录「规范字段 → 原始列名」的映射
- 单位缺失：`unit_source` 记录单位是从哪个字段读出来 / 怎么推测的
- 权重被改：`change_logs` 表记录每次修改的人、时间、前后值、原因
- 复核结论：每个异常点独立存 `review_status` + `reviewer_note`
