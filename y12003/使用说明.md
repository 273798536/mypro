# 批发赊销信用额度分析系统

## 快速启动

### 方法一：直接运行（加载样例数据）
```bash
python credit_analyzer.py
```
或
```bash
python credit_analyzer.py --sample
```

### 方法二：导入真实数据
1. 参考 `sample_data/` 目录下的样例格式准备数据
2. 修改 `credit_analyzer.py` 中的 `load_sample_data` 函数，或创建自己的数据加载函数

## 功能说明

### 1. 查看信用额度总览
- 显示所有客户的信用额度使用情况
- 按使用率排序，优先展示高风险客户
- 显示客户状态分布（正常/预警/逾期/冻结）

### 2. 查看单个客户详情
- 输入客户ID（如 C001）
- 显示：基础额度、有效额度、实际使用、可用额度、使用率
- 自动展示：待处理退货建议、临时额度到期提醒
- **业务员最关心**：直接显示能否发货

### 3. 检查能否发货
- 输入客户ID
- 可选择输入订单金额
- 系统自动判断并给出明确结论

### 4. 查看未认领回款
- 列出所有未匹配的回款记录
- 按客户分类统计

**触发回款未认领的条件：**
1. 回款记录没有关联客户ID
2. 回款金额与订单金额不匹配
3. 回款日期与订单日期差距过大（超过30天）
4. 智能匹配置信度低于40分，需要人工确认

### 5. 查看修正任务清单
- 高优先级任务：
  - 超过30天未处理的退货单
  - 已过期但状态未更新的临时额度
- 中优先级任务：
  - 超过14天未处理的退货单
  - 7天内即将到期的临时额度

### 6. 导出数据文件
导出文件保存在 `output/` 目录：
- `credit_summary.csv` - 信用额度汇总
- `unmatched_payments.csv` - 未认领回款
- `correction_tasks.csv` - 修正任务清单
- `full_data.json` - 完整数据（含所有明细）

## 核心逻辑

### 额度计算公式
```
有效额度 = 基础额度 + 当前生效的临时额度
实际占用 = 赊销总额 - 已回款 - 已批准退货
可用额度 = 有效额度 - 实际占用
使用率 = 实际占用 / 有效额度 × 100%
```

### 状态变化规则
| 使用率 | 状态 | 说明 |
|--------|------|------|
| < 80% | 正常 | 额度使用正常 |
| 80% - 90% | 预警 | 接近额度上限 |
| 90% - 100% | 逾期 | 额度即将用尽 |
| >= 100% | 冻结 | 额度已用尽，无法发货 |

**状态变化后自动触发：**
- 回款匹配逻辑重新计算
- 风险提示级别更新
- 发货权限动态调整

## 常见问题

### Q: 数据有缺失字段怎么办？
A: 系统设计时已考虑脏数据：
- 客户备注字段可记录特殊情况
- 销售订单缺失字段不影响核心计算
- 回款晚到的情况会保持待认领状态，不会乱匹配

### Q: 为什么有的回款不能自动匹配？
A: 为了避免错误匹配，当置信度低于40分时，系统不会自动处理，需要人工确认。可以在"查看未认领回款"中查看具体原因。

### Q: 退货占额如何处理？
A: 只有**已批准**的退货才会释放额度。待处理的退货会在修正建议中提示，处理后额度自动更新。

### Q: 临时额度过期了怎么办？
A: 系统会在修正任务清单中提醒，建议：
1. 立即更新临时额度状态
2. 评估客户是否需要续期
3. 如果超额使用，及时催缴
