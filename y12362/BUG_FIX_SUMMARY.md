# Bug修复总结 - 速度计算过度放大问题

## 问题描述

**现象**：产物有可运行入口和已生成报告，但核心检查结果不可靠。
- 关节1速度被报为 4297.18°/s
- 关节2速度被报为 5729.58°/s
- 关节3速度被报为 11459.16°/s

这些数值明显不是样例中 15°/0.2s、20°/0.2s 的真实量级，导致速度超限结论被系统性放大。

---

## 根因分析

**位置**：`robot_joint_checker/src/torque_calculator.py` 第71行

**问题代码**：
```python
vel = (angles[i + 1] - angles[i - 1]) / dt
velocities.append(math.degrees(vel))  # ❌ 错误
```

**分析**：
- `angles` 输入已经是以**度**为单位的角度值
- 差分计算 `(angles[i+1] - angles[i-1]) / dt` 得到的已经是 **度/秒**
- 但代码又调用了 `math.degrees()`，假设输入是弧度，进行了弧度到度的转换
- 结果：速度被放大了 `180/π ≈ 57.3` 倍

**验证**：
- 75 °/s × 57.2958 ≈ 4297 °/s ✓ (与报告中关节1的数值一致)
- 100 °/s × 57.2958 ≈ 5730 °/s ✓ (与报告中关节2的数值一致)
- 200 °/s × 57.2958 ≈ 11459 °/s ✓ (与报告中关节3的数值一致)

---

## 修复方案

**修复代码**：
```python
vel = (angles[i + 1] - angles[i - 1]) / dt
velocities.append(vel)  # ✅ 正确，直接使用度/秒
```

**修改文件**：[torque_calculator.py](file:///Users/mac/pro/solo/workspaces/y12362/robot_joint_checker/src/torque_calculator.py#L67-L77)
