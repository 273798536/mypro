# 热泵循环阈值预警 — 运营主管接手指南

## 一、整体流程

每天早会前跑一次 → 看终端摘要 → 有异常再查明细 → 需要时重新导出

## 二、目录说明（三个地方必须记住）

### 1. 放材料的地方：`input/`
```
input/
├── nameplate.csv   ← 设备铭牌（参数版本的源头，改了要记版本号）
├── samples.csv     ← 循环样本数据（每天新数据放这里）
└── note.txt        ← 后补说明（采样异常、临时调整等文字说明）
```
- 新的一天数据：直接覆盖或追加 `samples.csv`
- 铭牌参数变了：改 `nameplate.csv`，同时在 `note.txt` 里记录版本号
- 文件格式：CSV 优先，也支持 xlsx

### 2. 看异常的地方：`output/anomalies/`
```
output/
├── summary/      ← 终端摘要（文本 + JSON 各一份）
├── details/      ← 明细数据（有效明细 + 完整明细）
├── charts/       ← 图表（COP分布、预警饼图、温度趋势）
└── anomalies/    ← 异常数据（坏数据、采样缺口、无铭牌设备）👈 重点看
```
- 异常数据单独归档，不计入统计结论
- 每条异常都标了原因（数据为空？温度为负？进出水颠倒？采样间隔超30分钟？）
- 坏数据会标注「参考铭牌行」，方便溯源到原始设备

### 3. 重新导出的地方：命令行直接跑

```bash
python -m heatpump_alert.cli --input ./input --output ./output
```

参数：
- `-i / --input`：输入目录（默认 `./input`）
- `-o / --output`：输出目录（默认 `./output`）
- `--no-chart`：不生成图表（快一点）
- `--quiet`：静默模式，只输出 JSON 文件路径

每次运行会按时间戳生成新文件，不会覆盖之前的结果。
参数版本变化时，输出文件名带时间戳，方便对比不同版本的结果。

## 三、怎么快速判断有没有问题

1. **先看终端摘要最上面三行**：样本总数、坏数据数、采样缺口数
2. **再看预警数**：如果 > 0，去 `output/details/` 看是哪几条
3. **最后看设备维度**：哪台设备预警多，重点关注

## 四、边界样本怎么复算

把边界样本那条数据放进 `samples.csv`（可以单独放一个文件，用 `--input` 指定目录），重新跑命令就行。
图表和明细用的是同一份有效数据，口径一致，不用担心两边对不上。

## 五、文件命名约定

- 摘要：`summary_YYYYMMDD_HHMMSS.txt` 和 `result_YYYYMMDD_HHMMSS.json`
- 有效明细：`details_valid_YYYYMMDD_HHMMSS.csv`（只含纳入统计的正常数据）
- 完整明细：`details_full_YYYYMMDD_HHMMSS.csv`（全部数据，含标记）
- 异常明细：`anomalies_YYYYMMDD_HHMMSS.csv`（坏数据 + 采样缺口 + 无铭牌）
- 图表：`cop_by_device.png`、`alert_distribution.png`、`water_temp_trend.png`

## 六、预警规则说明

| 预警类型 | 触发条件 | 级别 | 是否计入统计 |
|---------|---------|------|-------------|
| 低COP预警 | COP < 铭牌COP下限 | 预警 | 是 |
| 高COP预警 | COP > 铭牌COP上限 | 预警 | 是（疑似异常） |
| 超温预警 | 出水温度 > 铭牌最高温度 | 预警 | 是 |
| 低温预警 | 出水温度 < 铭牌最低温度 | 预警 | 是 |
| 数据异常 | 空值/负值/进出水颠倒等 | 异常 | 否 |
| 采样缺口 | 相邻采样间隔 > 30 分钟 | 注意 | 否 |
| 无铭牌数据 | 设备编号在铭牌中找不到 | 注意 | 否 |
