# 热泵循环阈值预警 — 运营主管接手指南

## 一、整体流程

每天早会前跑一次 → 看终端摘要 → 有异常再查明细 → 需要时重新导出

**退出码约定**：0=成功，1=输入错误，2=输出错误，3=运行时异常（可被监控系统捕获）

---

## 二、目录说明（三个地方必须记住）

### 1. 放材料的地方：`input/`
```
input/
├── nameplate.csv   ← 设备铭牌（参数版本源头，改了要记版本号）
├── samples.csv     ← 循环样本数据（每天新数据放这里）
└── note.txt        ← 后补说明（采样异常、临时调整等文字说明）
```
- 新的一天数据：覆盖或追加 `samples.csv`
- 铭牌参数变了：改 `nameplate.csv`，同时在 `note.txt` 里记版本号，否则第二天没人记得
- 文件格式：CSV 优先，也支持 xlsx（文件名相同）
- 必填列缺失会直接报错并给出列名，按提示补充即可

### 2. 看异常的地方：`output/anomalies/`
```
output/
├── summary/      ← 终端摘要（文本 + JSON 各一份，内容一致）
├── details/      ← 明细数据（有效明细 + 完整明细）
├── charts/       ← 图表（COP分布、预警饼图、温度趋势）
└── anomalies/    ← 异常数据（坏数据、采样缺口、无铭牌设备）👈 重点看
```
- 异常数据单独归档，**不计入统计结论**，不会把结果带偏
- 每条异常都有「判定依据」和「_样本原始行号」，直接对照 CSV 原始行
- 坏数据会标注「参考铭牌行」，指向具体设备

### 3. 重新导出的地方：命令行直接跑

```bash
# 最常用：默认目录
python -m heatpump_alert.cli

# 显式指定（建议写进脚本，避免记错）
python -m heatpump_alert.cli -i ./input -o ./output

# 快一点：不生成图表
python -m heatpump_alert.cli --no-chart

# 被调度系统调用：静默模式，成功只输出 JSON 路径，失败仍提示
python -m heatpump_alert.cli --quiet
```

每次运行按时间戳生成新文件，不覆盖之前的结果。参数版本变化时，靠时间戳 + note.txt 追溯。

## 三、快速判断有没有问题（核心检查点）

### 3.1 先看终端摘要 6 个数字（从 summary/*.txt 开头读取）

| 数字 | 说明 | 异常处理 |
|---|---|---|
| 样本总数 | 跑了多少条 | 和昨天比差太多 → 查 samples.csv 是否漏导 |
| 坏数据数 | 剔除多少条 | >0 → 去 `anomalies/` 看原因，是真坏还是格式错 |
| 采样缺口数 | 断采多少段 | >0 → 看 note.txt 有没有说明，没说明去问现场 |
| 有效样本数 | 纳入统计的 | = 总数 - 坏 - 缺口 - 无铭牌 |
| 正常/预警数 | 正常 vs 预警 | 预警数突增 → 查设备是否故障 |
| 整体平均COP | 各台加权 | 明显偏离 ±0.5 → 查阈值或样本 |

### 3.2 重点复核：边界样本

每次 samples.csv 里备注含「边界样本」字样的都会被标记，终端摘要会显示：
```
边界样本数：N 条（其中预警 M 条）
```
如果 N≠你预期的边界数，说明备注写错了或数据被覆盖。
每条边界样本在 `details_full_*.csv` 里有 `边界样本=True` 标记，人工抽验直接筛。

### 3.3 口径一致性自证（不用你再对）

程序内部会断言：
- 正常数 + 预警数 == 有效样本数
- 坏数据数 == 数据异常类型数
- 写 CSV 后回读校验行数 == df 行数
- JSON 内 summary == 内存 summary

断言失败直接抛异常，不会给你一份自相矛盾的结果。

## 四、坏数据会被怎么处理

### 会被标记为「数据异常」并剔除（**不影响统计**）

| 识别规则 | 判定依据示例 |
|---|---|
| 数值为空 | `出水温度(℃):空值(原值=nan)[行14]` |
| 数值为负 | `出水温度(℃):负值(实际值=-5.0)[行20]` |
| 进出水颠倒 | `进出水温颠倒(出水=30.0℃<回水=46.5℃)[行15]` |
| 流量≤0 | `流量(m³/h):负值或零(实际值=0)[行X]` |

### 采样缺口怎么算

同设备相邻两条采样间隔 > 30 分钟 → 标记「采样缺口」，附带间隔分钟数。
通常是断电、重启、传感器离线等真实情况，不会带偏均值。

---

## 五、预警判定依据怎么读

每条有效样本在明细里有「判定依据」列，举例：
```
COP=4.3604 ∈ [3.8,5.2]；出水温度=61.0℃ > 最高=60.0℃
```
直接对照铭牌就能复核，不需要再查公式。

## 六、文件命名约定

- 摘要：`summary_YYYYMMDD_HHMMSS.txt`（终端同内容）
- 接口：`result_YYYYMMDD_HHMMSS.json`（结构化数据，含文件 md5 校验）
- 有效明细：`details_valid_YYYYMMDD_HHMMSS.csv`（只含纳入统计的数据，作图同源）
- 完整明细：`details_full_YYYYMMDD_HHMMSS.csv`（全部 23 条，含所有标记列）
- 异常明细：`anomalies_YYYYMMDD_HHMMSS.csv`（坏数据 + 缺口 + 无铭牌）
- 图表：`cop_by_device.png`、`alert_distribution.png`、`water_temp_trend.png`

## 七、预警规则速查

| 预警类型 | 触发条件（阈值来自铭牌） | 级别 | 计入统计 | 出现在哪 |
|---|---|---|---|---|
| 低COP预警 | COP < 铭牌COP下限 | 预警 | 是 | details_valid + 终端摘要 |
| 高COP预警 | COP > 铭牌COP上限 | 预警 | 是 | 同上 |
| 超温预警 | 出水温度 > 铭牌最高温度 | 预警 | 是 | 同上 |
| 低温预警 | 出水温度 < 铭牌最低温度 | 预警 | 是 | 同上 |
| 数据异常 | 空值/负值/进出水颠倒等 | 异常 | 否 | anomalies |
| 采样缺口 | 相邻采样间隔 > 30 分钟 | 注意 | 否 | anomalies |
| 无铭牌数据 | 设备编号在铭牌中找不到 | 注意 | 否 | anomalies |

## 八、常见错误提示（别慌，按提示做）

| 提示 | 原因 | 处理 |
|---|---|---|
| 输入目录不存在 | `input/` 没建或路径错 | mkdir 或传 `-i` 参数 |
| samples.csv 缺少必填列：['xxx'] | 导出时漏列或中文名 | 对照错误提示里的列名补全 |
| 采样时间格式无效（原始行：[...]） | 时间不是 YYYY-MM-DD HH:MM:SS | 修正格式后重跑 |
| nameplate.csv 存在重复设备编号 | 同一台设备写了两行 | 去重 |
| 创建输出目录 xxx 失败 | 磁盘满或权限 | 清磁盘/chmod |
| 部分文件写入有问题 | 中间某文件写失败 | 看 JSON 错误信息字段 + 终端提示 |
