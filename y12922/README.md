# 标注员一致性复盘

面向知识库运营的标注一致性复核工具。数据全部落本地 SQLite，服务重启后仍可查。

## 一、启动

```bash
# 安装依赖（首次）
npm install

# 同时启动前端（5173）和后端（3001）
npm run dev
```

打开浏览器访问 http://localhost:5173/

> 数据库文件位于 `api/data/review.db`，删除此文件等于清空所有数据。

## 二、导入批次

1. 首页右上角点「导入批次」。
2. 粘贴 JSON 格式的样本标注数据。格式：

```json
{
  "batchNo": "批次编号",
  "sourceFileName": "可选：来源文件名",
  "samples": [
    {
      "sampleKey": "样本唯一编号",
      "content": "样本内容（如用户问题）",
      "splitTag": "train 或 eval",
      "annotations": [
        { "annotator": "标注员A", "label": "是" },
        { "annotator": "标注员B", "label": "否" }
      ]
    }
  ]
}
```

3. 也可以点「载入示例批次」先用演示数据试手。
4. 点「导入」。

注意：同一批样本+同一批标注，第二次导入会自动命中指纹，直接复用已有结论，**不会**产生两份互相冲突的结论。

## 三、查看异常与反查

1. 在批次列表中点开一个批次。
2. 往下滑到「异常清单」。
3. 点任意一行展开反查面板，按顺序可见：
   - 异常本身（类型 / 严重度 / 状态）
   - 切分清单（该样本在 train 还是 eval，以及整批切分情况）
   - 每位标注员的原始标注
   - 处理意见（如已复核）
   - 结论依据

模型评审验收时，顺着一条异常一路往下翻，能查到切分清单和处理意见，反查链即完整。

## 四、复核与状态推进

1. 在异常行的右侧「复核」面板，填写：
   - 处理动作（重新标注 / 剔除样本 / 保留 / 重新切分）
   - 处理说明
   - 复核人
2. 点「保存处理意见」。
3. 批次顶部有「推进状态」按钮，按流程逐步推进：
   - 已导入 → 复核中 → 已复核 → 已导出

## 五、导出报告

1. 进入批次详情，点顶部「报告与对比」。
2. 点「生成报告」，右侧会预览报告。
3. 用下方按钮导出：
   - **导出 HTML**：下载可直接用浏览器打开的文件，能转给不懂代码的人看。
   - **打印为 PDF**：在浏览器打印对话框中另存为 PDF。

报告里的术语（一致率、Kappa、切分清单、评测集偏科等）都有大白话解释，附在「附录 · 术语」章节。

## 六、灰度对比

1. 同一页面「灰度对比」区，选择一个对照批次。
2. 点「对比」。结果会展示双方的一致率、Kappa、异常数、已处理数、偏科数。
3. 数据直接复用两批的既有处理记录，不会重复计算。

## 七、常见问题

- **服务重启后数据还在吗？**
  在。所有数据存在 `api/data/review.db`，SQLite 本地文件。

- **为什么二次导入同一个文件没有新建批次？**
  这是预期行为——系统用样本内容+标注算指纹，命中既有指纹就复用，避免产生冲突结论。

- **评测集偏科的结论是怎么来的？**
  比较 train 和 eval 中各标签的占比，相差超过 25 个百分点或某类在 eval 中超过 75% 会被标记为偏科。报告里有白话解释。
