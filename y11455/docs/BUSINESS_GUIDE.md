# 社区团购售后异常回执状态机 - 业务操作指南

## 一、系统核心价值

从团长退款、仓库复核到最终结算的完整追踪链路，核心解决：
- 少发/坏品走不同渠道但补偿金额对不上的责任归属问题
- 重复导入不重复计算（幂等）
- 改判不覆盖原始证据（可追溯）
- 冻结前后状态清晰可见

## 三、标准操作流程

### 3.1 流程概览

```
批次创建 → 附件补传 → 复核判定 → 【改判】 → 冻结结算 → 撤回归档
          ↓                        ↑
        少发 → 仓库渠道           撤回后重新提交
        坏品 → 物流渠道
```

### 3.2 步骤详解

#### 步骤1: 批次创建（幂等）

- 同批次号重复提交不会重复导入
- 保留：来源文件名、原始行号、原始数据JSON
- 解析后的值独立存储，不覆盖原始数据

**幂等验证:
```
第一次导入: 10条记录 → 创建10条
第二次导入（同批次号）: 返回已存在批次，不创建新记录
```

#### 步骤2: 附件补传

补传短信截图或异常照片作为证据
- 支持多次补传，全部保留
- 记录上传人、时间、类型
- 不删除历史附件

#### 步骤3: 复核改判

**正常复核**:
- 批量选择多条记录
- 设定状态：已通过 / 已驳回
- 可调整补偿金额和责任方

**人工改判**:
- 记录改判理由必填
- 保留改判历史（原状态→新状态）
- 标记`is_manually_overruled = true
- 不覆盖原始复核结果

#### 步骤4: 冻结结算

导出前冻结，防止数据变动：
- 冻结后状态变为`已冻结`
- 记录冻结前状态
- 冻结期间不能复核、改判
- 解冻后恢复冻结前状态

#### 步骤5: 撤回归档

**撤回**:
- 状态变为`已撤回`
- 可重新提交进入待复核
- 保留撤回记录可查

**归档**:
- 已通过/已驳回的记录可归档
- 归档后不可修改

## 四、边界场景处理

### 4.1 重复提交

**场景**: 同一Excel导入多次

**处理**:
- 通过`batch_no`作为幂等键
- 重复批次返回`is_duplicate_batch: true`
- 不创建任何新数据

**失败路径**: 忘记传错批次号 → 数据重复导入

**修正方式**: 撤回错误批次，用正确批次号重新导入

---

### 4.2 撤回后再提交

**场景**: OD20240501001 撤回后需要重新处理

**状态流转**:
```
待复核 → 已通过 → 【撤回 → 已撤回 → 【重新提交】 → 待复核
```

**允许的状态转换见:

| 当前状态 | 可转换到 |
|----------|----------|
| 待复核 | 复核中、已通过、已驳回、已撤回、已冻结 |
| 复核中 | 已通过、已驳回、待复核、已撤回、已冻结 |
| 已通过 | 已冻结、已归档、已撤回 |
| 已驳回 | 已冻结、已归档、已撤回 |
| 已冻结 | 已通过、已驳回、待复核、复核中 |
| 已撤回 | 待复核、已冻结 |
| 已归档 | - |

---

### 4.3 部分失败

**场景**: 导入100条，3条解析失败

**处理**:
- 成功97条正常入库
- 失败3条返回详细错误（行号+错误信息+原始数据）
- 批次统计：total=100, success=97, fail=3

**失败路径**: Excel列名不对 → 全部解析失败

**修正方式**: 修改Excel列名 → 新批次号重新导入

---

### 4.4 人工改判

**场景**: 系统判定仓库责任，实际是物流责任

**处理**:
1. 查询回执详情
2. 执行改判操作，填写理由
3. 系统记录：
   - 原状态、原金额、原责任方
   - 新状态、新金额、新责任方
   - 改判理由、操作人、时间

**报表变化**:
- `is_manually_overruled`: false → true
- `manual_review_reason`: 显示改判理由
- 改判历史表新增一条记录

---

### 4.5 导出前冻结

**场景**: 导出报表前需要冻结数据

**处理**:
1. 选择需要导出的记录
2. 执行冻结（原因：待导出前冻结）
3. 导出报表
4. 导出后可解冻或直接归档

**报表变化**:
- `is_frozen`: true
- `status_before_freeze`: 记录冻结前状态
- `current_status`: 已冻结

## 六、常见问题

### 6.1 如何追溯原始证据？

查看回执详情接口：`GET /api/v1/receipts/{id}`

返回包含：
- `original_leader_refund_id` - 关联团长退款原始记录ID
- `original_warehouse_review_id` - 关联仓库复核原始记录ID
- `attachments` - 所有附件列表
- `status_histories` - 完整状态变更历史
- `overrule_histories` - 改判历史
- `freeze_records` - 冻结记录

### 6.2 金额对不上怎么办？

查看 `amount_diff` 字段：
- amount_diff > 0: 补偿金额 > 退款金额
- amount_diff < 0: 补偿金额 < 退款金额
- amount_diff = 0: 金额一致

点击查看详情中的改判历史和冻结记录，确定责任归属。

### 6.3 如何确认数据来源？

每个回执关联的原始数据记录包含：
- `original_data` - 原始导入的JSON数据
- `original_row_no` - Excel原始行号
- `source_file` - 来源文件名
