# 港口堆场箱位三维图工具系统 - 产品需求文档

## 1. 产品概述

### 1.1 产品名称
港口堆场箱位三维图工具系统

### 1.2 目标用户
- **主要用户**：运维组工作人员
- **次要用户**：仿真工程师

### 1.3 核心价值
将传统的表格颜色和口头约定升级为可追溯、可管理的数字化工具，实现港口堆场箱位异常检测、处理记录统一管理和历史追溯。

### 1.4 背景与问题
- **现状问题**：仿真工程师处理港口堆场箱位三维图时依赖表格颜色和口头约定，缺乏系统性管理
- **改进目标**：实现"每个结论都能反查"，确保处理记录的完整性和可追溯性

## 2. 功能需求

### 2.1 核心功能模块

#### 2.1.1 数据导入模块
- **支持格式**：Excel、CSV、JSON等常见数据格式
- **导入流程**：
  1. 用户选择数据文件
  2. 系统解析数据结构
  3. 自动识别箱位信息和位置数据
  4. 生成导入报告
- **数据校验**：
  - 必填字段检查
  - 数据格式验证
  - 范围检查（位置坐标、尺寸等）

#### 2.1.2 异常检测与筛选模块
- **异常类型**：
  - 模型重叠：多个箱位占用相同空间位置
  - 相机视角丢失：三维视角异常或丢失
  - 尺寸超限：箱位尺寸超出规定范围
  - 位置偏移：箱位位置偏离预定坐标
- **筛选功能**：
  - 按异常类型筛选
  - 按严重程度筛选（高危、中危、低危）
  - 按时间范围筛选
  - 按导入批次筛选
- **异常状态**：
  - 待处理
  - 处理中
  - 已处理
  - 已复核

#### 2.1.3 异常详情查看模块
- **详情内容**：
  - 异常基本信息（类型、严重程度、发现时间）
  - 来源信息（数据来源、导入批次）
  - 风险备注（发现时的风险描述）
  - 处理意见（处理方案和建议）
  - 关联记录（相关的处理历史）
- **追溯功能**：
  - 顺着单条异常往回查
  - 显示完整的处理链条
  - 关联的风险备注和处理意见

#### 2.1.4 处理记录管理模块（核心）
- **记录统一性**：
  - 明细联动和截图导出共用同一批处理记录
  - 界面展示和报告生成使用统一数据源
  - 避免数据不一致的问题
- **记录内容**：
  - 处理人
  - 处理时间
  - 处理操作
  - 处理结果
  - 备注信息
- **操作类型**：
  - 添加风险备注
  - 填写处理意见
  - 修改异常状态
  - 复核确认
  - 截图导出

#### 2.1.5 历史追溯模块
- **追溯内容**：
  - 模型重叠复核通过的历史记录
  - 显示修改人、修改时间、修改原因
  - 显示完整的修改前后对比
- **审计功能**：
  - 记录所有操作的历史
  - 支持按人员、时间、操作类型查询
  - 生成操作日志报告

#### 2.1.6 三维可视化模块
- **可视化功能**：
  - 堆场箱位三维展示
  - 视角控制（旋转、缩放、平移）
  - 异常位置高亮显示
  - 相机视角保存与恢复
- **相机管理**：
  - 保存常用视角
  - 相机视角状态监控
  - 异常状态记录（视角丢失时自动记录）

#### 2.1.7 导出功能模块
- **截图导出**：
  - 当前视图截图
  - 带标注的异常截图
  - 导出时自动关联处理记录
- **报告导出**：
  - 异常汇总报告
  - 处理进度报告
  - 历史追溯报告
- **数据导出**：
  - 处理记录导出（Excel、CSV）
  - 异常明细导出

### 2.2 示例数据功能
- **触发条件**：用户首次打开工具时
- **示例数据内容**：
  - 模拟的堆场箱位数据
  - 预设的异常记录
  - 示例处理历史
- **目的**：让仿真工程师不用先造半天表才能看懂工具

### 2.3 使用说明文档
- **文档内容**：
  - 启动工具的步骤
  - 导入数据的流程
  - 查看异常的技巧
  - 导出结果的方法
  - 常见问题处理（特别是相机视角丢失）
- **文档风格**：
  - 实用导向，避免宣传页风格
  - 步骤清晰，操作性强
  - 重点突出故障处理

## 3. 用户交互流程

### 3.1 主流程
1. **启动工具** → 显示三维视图
2. **导入数据** → 系统自动检测异常
3. **查看异常列表** → 筛选和搜索
4. **点进异常详情** → 查看来源和处理意见
5. **处理异常** → 添加风险备注和处理意见
6. **复核确认** → 更新异常状态
7. **导出结果** → 生成报告或截图

### 3.2 异常追溯流程
1. 选择目标异常记录
2. 点击"查看详情"
3. 显示完整的处理链条
4. 包含风险备注和处理意见
5. 支持导出追溯报告

### 3.3 历史追溯流程
1. 进入历史记录页面
2. 筛选查询条件（人员、时间、操作类型）
3. 查看模型重叠复核通过的详细记录
4. 显示修改人、修改时间、为什么改

## 4. 数据模型设计

### 4.1 核心实体
- **ContainerPosition**：箱位位置信息
- **AnomalyRecord**：异常记录
- **ProcessingRecord**：处理记录
- **HistoryLog**：历史日志
- **CameraState**：相机状态
- **ExportRecord**：导出记录

### 4.2 关系设计
- AnomalyRecord 1:N ProcessingRecord（一对多）
- AnomalyRecord 1:N HistoryLog（一对多）
- ProcessingRecord 1:1 ExportRecord（一一对应）

## 5. 性能需求
- 界面响应时间：< 2秒
- 数据导入速度：1000条/秒
- 三维渲染帧率：≥ 30FPS
- 异常检测时间：< 5秒（10000条数据）

## 6. 安全性需求
- 用户操作日志完整记录
- 敏感操作需要确认
- 数据备份机制
- 异常状态自动告警

## 7. 验收标准
- [ ] 仿真工程师能快速理解工具（有示例数据）
- [ ] 顺着一条异常往回查，能查到风险备注和处理意见
- [ ] 模型重叠复核通过后，历史里要知道是谁改的、什么时候改的、为什么改
- [ ] 明细联动和截图导出共用同一批处理记录
- [ ] 操作文档清晰实用（不是宣传页）
