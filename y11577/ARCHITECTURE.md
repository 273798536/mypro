# 外协加工对账重试补偿队列系统 - 架构设计

## 系统概述

本系统用于解决外协加工对账过程中的数据一致性问题，支持夜间抢修无单场景下的补录流程，处理同一批半成品分批返工后结算单容易多扣引出的重复和冲突问题。

## 核心设计原则

1. **幂等性保证**：重复请求只能更新同一条事实，不能悄悄多算
2. **可追溯性**：报表数字要能追到单条记录
3. **数据隔离**：坏数据不能进汇总，但要在失败列表里看得到原因
4. **权限分级**：录入、复核、主管、只读查看的可见字段和可操作动作严格区分
5. **管理视图**：老板关注可重试分类、死信处理、恢复后续跑

## 技术栈

- **后端框架**: FastAPI
- **ORM**: SQLAlchemy 2.0
- **数据库**: PostgreSQL
- **认证**: JWT Token
- **任务队列**: APScheduler (内置重试队列)
- **数据校验**: Pydantic

## 核心业务流程

### 1. 数据录入流程
```
外部回执提交 → 幂等性检查 → 权限校验 → 数据校验 → 存入原始表 → 入队
                    │
                    └→ 已存在 → 更新同一条记录
```

### 2. 重试补偿队列流程
```
排队 → 首次处理 → 成功 → 补偿入账 → 关闭
          │
          └→ 失败 → 重试(限3次) → 成功 → 补偿入账 → 关闭
                      │
                      └→ 失败 → 死信队列 → 人工接管
                                                      │
                                                      └→ 修正后重新入队
```

### 3. 权限矩阵

| 角色 | 可见字段 | 可操作动作 |
|------|---------|-----------|
| 录入员 | 基础字段，无金额敏感字段 | 录入、提交、查看自己录入的数据 |
| 复核员 | 完整字段 | 复核、驳回、查看全部待复核数据 |
| 主管 | 完整字段 + 统计数据 | 审核、人工接管、死信处理、查看报表 |
| 只读 | 非敏感字段 | 查看、导出报表 |

## 核心数据表设计

### 1. 外协送货单 (outsource_delivery)
- 主键: delivery_id
- 幂等键: idempotent_key (供应商+送货单号+日期)
- 业务字段: 供应商、半成品编码、数量、单价、金额
- 状态字段: 状态(待录入/已录入/已复核/已入账)
- 审计字段: 创建人、创建时间、更新人、更新时间

### 2. 返修记录 (repair_record)
- 主键: repair_id
- 幂等键: idempotent_key (送货单ID+返修批次)
- 业务字段: 返修原因、返修数量、返修费用、责任方
- 关联字段: delivery_id

### 3. 扣款明细 (deduction_detail)
- 主键: deduction_id
- 幂等键: idempotent_key (送货单ID+扣款类型)
- 业务字段: 扣款类型、扣款金额、扣款原因
- 关联字段: delivery_id, repair_id

### 4. 补偿队列 (compensation_queue)
- 主键: queue_id
- 业务键: business_key (关联业务记录)
- 状态: 待处理/处理中/成功/失败/死信
- 重试次数: retry_count
- 最大重试次数: max_retries
- 下次重试时间: next_retry_at
- 最后错误信息: last_error
- 处理日志: process_logs (JSON)

### 5. 班次记录 (shift_record)
- 主键: shift_id
- 幂等键: idempotent_key (日期+班次+班组)
- 业务字段: 班组、人员、工时、产量

### 6. 临时补录单 (temporary_supplement)
- 主键: supplement_id
- 幂等键: idempotent_key (补录类型+日期+关联单号)
- 业务字段: 补录原因、补录内容、关联单据

### 7. 权限相关表
- users: 用户表
- roles: 角色表
- user_roles: 用户角色关联表
- permissions: 权限表
- role_permissions: 角色权限关联表

## 幂等性实现方案

使用组合幂等键 + 数据库唯一约束:
1. 每个业务表都有 `idempotent_key` 字段
2. 对该字段建立唯一索引
3. 提交时先查询是否存在
4. 存在则更新，不存在则插入
5. 数据库层面保证唯一性

## 报表追溯方案

1. 每个汇总记录都有 `source_ids` 字段，存储构成该汇总的所有原始记录ID
2. 报表页面支持点击数字下钻到原始记录列表
3. 原始记录支持查看完整的处理日志和变更历史

## 坏数据处理方案

1. 数据校验失败的记录存入 `failed_records` 表
2. 失败记录包含: 原始数据、失败原因、校验时间
3. 失败列表支持查看、修正、重新提交
4. 坏数据永不进入正式汇总表
