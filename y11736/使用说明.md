## 🔄 标准业务流程

### 流程1：正常冻结 → 申诉 → 解冻

```
1. 创建冻结
   python main.py freeze create \
     --merchant-code M001 \
     --order-no ORD202401010001 \
     --amount 1000 \
     --reason "违规冻结-虚假发货" \
     --violation-no V2024001

2. 商家申诉
   python main.py appeal create \
     --violation-no V2024001 \
     --reason "已发货，有物流凭证" \
     --evidence "物流截图、发货单"

3. 审核申诉（通过）
   python main.py appeal audit \
     --appeal-no AP2024001 \
     --result approved \
     --unfreeze-amount 1000

4. 执行解冻
   python main.py unfreeze \
     --freeze-no FZ20240101000001 \
     --amount 1000 \
     --reason "申诉通过全额解冻" \
     --type full \
     --appeal-no AP2024001
```

### 流程2：部分解冻场景

```
1. 创建冻结 2000元
2. 申诉部分通过，建议解冻 1200元
3. 执行部分解冻
   python main.py unfreeze \
     --freeze-no FZxxx \
     --amount 1200 \
     --reason "申诉通过部分解冻" \
     --type partial

4. 此时状态变为 partially_unfrozen，剩余 800元仍冻结
5. 后续可继续解冻剩余部分
```

### 流程3：批量导入历史数据

```
# 按依赖顺序导入（重要！）
python main.py import-data merchants --file 商家表.xlsx
python main.py import-data orders --file 订单表.xlsx
python main.py import-data violations --file 违规表.xlsx
python main.py import-data appeals --file 申诉表.xlsx
python main.py import-data freezes --file 冻结表.xlsx
python main.py import-data unfreezes --file 解冻表.xlsx

# 导入后执行审计
python main.py audit
```

## 🚨 异常处理与风险提示

### 系统自动检测的风险

| 风险类型 | 触发场景 | 风险等级 | 处理建议 |
|---------|---------|---------|---------|
| **冻结范围扩大** | 同一商家连续多次冻结，金额逐次增长超过50% | 🔴 高风险 | 核查是否存在过度冻结 |
| **余额未回写** | 申诉通过超过24小时但未执行解冻 | 🟡 警告 / 🔴 高风险 | 立即执行解冻操作 |
| **重复解冻** | 同一冻结记录24小时内多次解冻 | 🔴 高风险 | 核查是否重复操作 |
| **余额不匹配** | 实际冻结金额与余额表记录不一致 | 🔴 高风险 | 执行 `python main.py audit` 修复 |
| **脏数据** | 导入数据缺少必填字段或格式错误 | 🟡 警告 | 查看导入日志修正后重试 |

### 异常场景及解决方案

#### 场景1：导入时提示"商家不存在"
```
原因：订单/违规数据引用了未导入的商家
解决：先导入商家数据，再导入关联数据
```

#### 场景2：解冻时提示"解冻金额超过剩余冻结金额"
```
原因：解冻金额 > 剩余冻结金额
解决：
1. 查询当前冻结状态：python main.py freeze status --freeze-no FZxxx
2. 调整解冻金额不超过剩余金额
3. 如剩余金额为0，说明已全部解冻
```

#### 场景3：申诉审核时提示"状态无法转换"
```
原因：申诉已处理过或状态不支持该操作
解决：
1. 查看申诉状态：检查是否已审核
2. 只能对 pending 状态的申诉进行审核
```

#### 场景4：数据导入后余额不对
```
解决：执行全量审计自动修复
python main.py audit
```

## 💡 最佳实践

1. **操作前先查询**：解冻前先用 `freeze status` 确认当前状态
2. **定期执行审计**：每天执行 `python main.py audit` 确保数据一致
3. **风险检测要常跑**：批量操作后执行 `risk-check`
4. **保留操作痕迹**：所有操作都会自动记录审计日志，可随时追溯
5. **导入顺序不能乱**：商家 → 订单 → 违规 → 申诉 → 冻结 → 解冻
6. **异常不要慌**：系统会自动提示风险，按提示处理即可

## ❓ 常见问题

**Q: 数据库文件在哪？可以迁移吗？**
A: 数据库文件是 `freeze_data.db`，直接复制即可迁移。

**Q: 可以同时多人使用吗？**
A: SQLite支持多读单写，建议同一时间只有一人执行写操作。

**Q: 数据删除了能恢复吗？**
A: 所有操作都有审计日志，但删除操作不可恢复，请谨慎操作。

**Q: 能连接MySQL吗？**
A: 修改 `config.py` 中的 `DATABASE_URL` 即可支持MySQL等数据库。
