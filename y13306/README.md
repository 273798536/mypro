# 病历问答灰度对比系统

## 项目概述

专为风控运营团队设计的病历问答模型灰度评测对比系统。解决了以下核心问题：

- ✅ **接口与CSV状态一致**：负责人从接口查明细，状态与导出的CSV完全一致
- ✅ **撤回与结论关联**：撤回记录与最终结论打通，完整追溯变更轨迹
- ✅ **重复评测检测**：自动识别重复评测数据，避免乱材料干扰
- ✅ **改判有解释**：新旧模型对比有明确的改判说明，能解释为什么变了
- ✅ **历史可追溯**：人工确认前后的变化全部进入历史，复盘时能说清来龙去脉

## 技术栈

### 后端
- **框架**: Node.js + Express + TypeScript
- **ORM**: Prisma
- **数据库**: PostgreSQL
- **核心功能**: 评测管理、CSV导入导出、历史变更追踪

### 前端
- **框架**: React 18 + TypeScript
- **构建工具**: Vite
- **UI组件**: Ant Design 5.x
- **路由**: React Router

## 快速开始

### 方式一：一键启动（推荐）

```bash
chmod +x start.sh
./start.sh
```

### 方式二：手动启动

#### 1. 环境准备

确保已安装：
- Node.js >= 18.x
- PostgreSQL >= 14.x
- npm >= 9.x

#### 2. 配置数据库

创建数据库：
```sql
CREATE DATABASE medical_gray_compare;
```

复制并修改环境变量：
```bash
cp .env.example .env
# 修改 DATABASE_URL 为你的数据库连接信息
```

#### 3. 安装依赖

```bash
npm install
```

#### 4. 初始化数据库和种子数据

```bash
npm run db:setup
```

#### 5. 运行业务场景测试

```bash
npm run test:scenario
```

此命令将运行8个完整的业务场景测试，模拟周一早会前的真实工作流程。

#### 6. 启动服务

```bash
# 同时启动前后端
npm run dev

# 仅启动后端
npm run dev:server

# 仅启动前端
npm run dev:client
```

#### 7. 访问应用

- 前端管理后台: http://localhost:5173
- 后端API: http://localhost:3001
- 健康检查: http://localhost:3001/api/health

## 功能特性

### 1. 评测记录管理
- 单条/批量创建评测记录
- 支持按批次、状态、模型版本、是否重复等多维度筛选
- 分页查询，支持大数据量

### 2. 状态管理（6种状态）
- `待评测` - 已创建未判定
- `已评测` - 模型已输出判定结果
- `已撤回` - 人工撤回，需关联最终结论
- `已人工确认` - 人工复核通过
- `已改判` - 人工修改了判定结果
- `重复评测` - 相同病历+问题的重复数据

### 3. 撤回与结论关联
- 支持对有问题的记录执行撤回
- 撤回记录必须关联最终正确结论
- 详情页清晰展示撤回原因、操作人、时间、关联的结论

### 4. 重复检测
- 基于 `病历ID + 问题ID` 自动检测重复
- 重复数据标记为 `重复评测` 状态
- 记录重复源ID，可追溯

### 5. 新旧模型对比
- 新模型评测时自动匹配旧模型对相同问题的判定
- 生成可视化对比卡片
- 自动生成改判解释，说明为什么变了

### 6. 历史变更追踪
- 所有操作（创建、更新、撤回、确认、改判）全部记录
- 记录字段级别的变更：原值→新值
- 记录操作人、时间、变更原因
- 时间线展示，清晰直观

### 7. CSV导入导出
#### 导入
- 支持批量导入评测数据
- 自动检测重复
- 导入失败时给出详细错误信息

#### 导出（28个字段，与接口完全一致）
1. 病历ID
2. 问题ID
3. 问题内容
4. 模型回答
5. 标准答案
6. 模型名称
7. 模型类型
8. 模型版本
9. 是否正确
10. 置信度
11. 错误类型
12. **状态**（与接口一致）
13. 判定理由
14. 改判理由
15. **是否重复**（与接口一致）
16. 重复源记录ID
17. **是否有撤回**（与接口一致）
18. 撤回原因
19. 撤回操作人
20. 撤回时间
21. 关联结论ID
22. 最终结论状态
23. 最终结论结果
24. **新旧模型对比说明**
25. 确认人
26. 确认时间
27. 创建时间
28. 评测时间

### 8. 统计概览
- 总记录数、已评测、正确、错误
- 准确率统计
- 各状态数量统计
- 重复、撤回数量统计

## 数据库设计

### 核心表

#### `ModelVersion` - 模型版本
- 存储旧模型、新模型、灰度模型的版本信息

#### `EvaluationRecord` - 评测记录（核心表）
- 存储每一条病历问答的评测结果
- 支持状态、重复标记、撤回标记、最终结论关联
- 关联模型版本、撤回记录、历史变更

#### `WithdrawalRecord` - 撤回记录
- 存储撤回原因、操作人、关联的最终结论ID
- 与评测记录一对一关联

#### `ChangeHistory` - 历史变更
- 记录所有字段级别的变更
- 支持完整的审计追踪

#### `ImportBatch` - 导入批次
- 记录每次CSV导入的信息

## 常见问题

### Q: 接口和CSV的状态不一致怎么办？
A: 系统设计时已保证状态字段完全同源。如发现不一致，请运行 `npm run test:scenario` 验证场景7。

### Q: 撤回记录后忘记关联结论怎么办？
A: 在详情页会显示黄色警告提示「尚未关联最终结论」，点击「关联结论」按钮即可补录。

### Q: 为什么有的记录有「新旧模型对比说明」，有的没有？
A: 只有当新模型评测了旧模型之前评测过的相同问题时，才会自动生成对比说明。

### Q: 如何查看一条记录的完整变更历史？
A: 进入详情页，下拉到「历史变更记录」区域，可查看时间线形式的完整变更轨迹。

### Q: CSV导出的28个字段太多，可以自定义吗？
A: 当前版本为了保证数据完整性，默认导出全部28个字段。如需自定义导出字段，可修改 `server/src/services/csv.service.ts` 中的 `exportToFile` 方法。
