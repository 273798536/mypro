# 海上施工禁区核查系统 - 使用说明

## 从空目录跑通流程

### 前置条件
- Python 3.7+
- curl

---

## 第一步：启动

### 1.1 首次环境配置
```bash
# 1. 进入目录
cd /path/to/project

# 2. 执行一键配置
./setup.sh
```

### 1.2 启动服务并加载样例数据
```bash
./run_demo.sh
```

### 1.3 验证服务
```bash
curl http://localhost:5001/api/health
```
返回 `{"status": "ok"}` 即为启动成功。

### 1.4 停止服务
```bash
./stop.sh
```

---

## 第二步：导入

### 2.1 导入核查记录
```bash
curl -X POST http://localhost:5001/api/records/import \
  -H "Content-Type: application/json" \
  -d '{
    "record_no": "HJ202606006",
    "project_name": "项目名称",
    "construction_area": "施工区域",
    "coordinates": "经度,纬度",
    "planned_date": "2026-06-15",
    "construction_type": "施工类型",
    "submitter": "提交人"
  }'
```

**必填字段**：`record_no`、`project_name`、`construction_area`、`planned_date`

### 2.2 导入气象预报（补录）
```bash
curl -X POST http://localhost:5001/api/forecasts/import \
  -H "Content-Type: application/json" \
  -d '{
    "record_id": 1,
    "forecast_date": "2026-06-13",
    "wind_level": 5,
    "wave_height": 1.8,
    "visibility": 6,
    "forecast_source": "预报来源",
    "forecast_time": "2026-06-12 08:00:00",
    "is_delayed": 0
  }'
```

**说明**：
- `record_id` 是核查记录的ID，从 `/api/records` 接口获取
- `is_delayed` 设为 1 表示预报晚到，需同时填写 `delay_reason`
- 导入预报后系统会**自动重新评估风险**，旧评估结果保留在历史记录中，不覆盖

### 2.3 手动触发评估
```bash
# 评估全部记录
curl -X POST http://localhost:5001/api/assess \
  -H "Content-Type: application/json" \
  -d '{"assessor": "你的名字"}'

# 评估单条记录
curl -X POST http://localhost:5001/api/assess \
  -H "Content-Type: application/json" \
  -d '{"record_id": 3, "assessor": "你的名字"}'
```

### 3.2 查看单条记录详情
```bash
curl http://localhost:5001/api/records/3
```

返回内容包含：
- 记录基本信息
- 关联的气象预报数据（含延迟标记）
- 所有版本的风险评估历史
- 异常记录及下一步操作
- 评估变更历史

### 3.3 异常类型说明

| 异常类型 | 严重程度 | 下一步 | 说明 |
|---------|---------|-------|------|
| FORECAST_DELAYED | warning | 补材料 | 风浪预报晚到，数据过时 |
| FORECAST_MISSING | error | 补材料 | 缺失施工日期的预报数据 |
| HIGH_RISK | error | 改口径 | 风浪条件超出安全阈值 |
| AREA_CONFLICT | error | 改口径 | 施工区域涉及敏感海域 |
| DATA_INCOMPLETE | warning | 补材料 | 记录字段不完整 |

### 3.4 标记异常已解决
```bash
curl -X POST http://localhost:5001/api/anomalies/1/resolve \
  -H "Content-Type: application/json" \
  -d '{"resolution_note": "已联系预报台补发最新数据"}'
```

## 第四步：导出结果

### 4.1 导出全部记录报告
```bash
# TXT 格式（自动下载）
curl -OJ http://localhost:5001/api/export

# JSON 格式
curl "http://localhost:5001/api/export?format=json"
```

### 4.2 导出单条记录报告
```bash
curl -OJ "http://localhost:5001/api/export?record_id=3"
```

### 4.3 报告内容说明

报告包含以下部分：
1. **记录基本信息**：编号、项目、区域、坐标、日期等
2. **风险评估结果**：等级、评分、版本号、评估时间
3. **受影响结论**：哪些结论因数据问题不可靠
4. **气象预报数据**：每条预报的风级、浪高、能见度、来源
5. **异常记录**：每个异常的描述、下一步操作（补材料/改口径）
6. **评估变更历史**：风险等级变化记录及原因
7. **风浪预报晚到特别说明**（如适用）：
   - 为什么被拦截
   - 影响范围
   - 处理建议

---

## 风浪预报晚到场景处理流程

当遇到 `FORECAST_DELAYED` 异常时：

1. 系统自动将风险等级设为 `pending`
2. 异常列表中标记为「补材料」
3. 受影响结论明确列出：
   - 风险分层结论暂不可靠
   - 施工许可审批需暂缓
   - 安全作业时间窗口需要重新计算
4. 导出报告末尾用专门区块说明拦截原因
5. 补录最新预报后，系统自动重新评估，生成新版本
6. 旧版本保留在历史记录中，可追溯
