# 采样缺口处理流程 · 不急着算完，先给原因和影响范围

> **核心原则**: 发现采样缺口时，立即中止当前误差合成计算，输出「待确认报告」，不得先补数据再出结果。

---

## 一、什么算「采样缺口」

满足以下**任一**情况即判定为存在采样缺口（GAP）：

| 缺口类型 | 判定标准 | 典型场景 |
|:---|:---|:---|
| **时序缺口** | 相邻两个采样点的时间间隔 $\Delta t > 3 \times$ 设定采样间隔 | 拍照漏帧、风洞重启、操作员中途打断 |
| **空间缺口** | 沿程/法向测站连续缺失 ≥ 1 个预设位置 | 某个位置烟线未点燃、该区域被遮挡 |
| **数据质量缺口** | 单张照片清晰度评分 < 5/10 或烟线不可识别 | 镜头起雾、逆光、快门不同步 |
| **环境参数缺口** | 风速/温度/气压任一参数在该采样点无同步记录 | 仪器掉线、数据采集软件崩溃 |
| **补备注缺口** | 现场照片中已用笔标注「此帧异常重拍」但未看到重拍照 | 原始与补拍照片归档时错位 |

## 二、处理流程（严格按顺序走，不许跳步）

```
┌─────────────────────────────────────────┐
│  Step 1: 发现缺口（任何人都可触发）     │
│  · 图像分析时发现不可识别帧            │
│  · 数据对齐时发现编号不连续            │
│  · 复核时发现参数缺失                  │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 2: 登记 — 不许跳过               │
│  · 填写下方「缺口登记表」每条GAP      │
│  · 在状态追踪看板标记「⚠️ 含缺口」    │
│  · 邮件/群消息通知实验师小林            │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 3: 输出「待确认报告」            │
│  · 报告首页数据完整性标志选「⚠️」     │
│  · 报告§六填写缺口详情                 │
│  · 结论中明确写「本结论基于___个有效点，│
│    缺失___个点，若补全总误差预计变化___」│
│  · 不许输出「最终结论」字样             │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 4: 原因排查 — 24小时内完成        │
│  · 查现场照片时间戳序列                 │
│  · 查风洞运行日志                       │
│  · 查数据采集软件日志                   │
│  · 问当值操作员                         │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 5: 影响范围评估                   │
│  · 缺口是否落在敏感区域（边界层梯度区） │
│  · 缺口前后数据是否有突变               │
│  · 用插值估算缺口处数值（标注为估算值） │
│  · 给出「含估算 vs 不含估算」两套结果   │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 6: 补证据 / 判无效                │
│  · 能补拍 → 安排补实验，补数据进报告    │
│  · 能从日志恢复 → 恢复后重新计算        │
│  · 无法恢复 → 标记该点为「已排除」，    │
│    报告中说明排除原因，总误差单独标注   │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│  Step 7: 关闭缺口                       │
│  · 在缺口登记表「关闭状态」打✅        │
│  · 在报告§六「是否已补」列更新          │
│  · 更新状态追踪看板                     │
└─────────────────────────────────────────┘
```

## 三、缺口登记表（每次发现立即填写）

> 完整记录见本目录下 `缺口登记表_YYYYMMDD.csv` 或以下表格

| 字段 | 填写说明 | 示例 |
|:---|:---|:---|
| **缺口编号** | GAP-年月日-序号 | GAP-20260614-001 |
| **发现人** | 谁第一个发现的 | 图像分析员小李 |
| **发现时间** | YYYY-MM-DD HH:MM | 2026-06-14 15:32 |
| **关联报告编号** | 对应哪份误差报告 | ERR-20260614-003 |
| **缺口类型** | 时序/空间/质量/环境/补备注 | 空间缺口 |
| **缺口位置** | 采样序号范围 + 照片编号 | 序号#15~#17，照片#045~#047 |
| **缺失内容** | 具体少了什么数据 | 法向位置y=20mm处3个连续测点的位移数据 |
| **初步原因假设（1~3条）** | 不要空着，哪怕是猜测 | 1. 烟丝在该位置未发烟；2. 该角度逆光；3. 操作员漏拍 |
| **影响误差分量** | 哪些分项会受影响 | §3.4 边界层项 + §3.2 扩散误差 |
| **无缺口时结果（估算）** | 粗估一下如果不缺会怎样 | 估算总误差约增加±0.3% |
| **当前状态** | 🔴 待处理 / 🟡 排查中 / 🟢 已补 / ⚫ 已判无效 | 🟡 排查中 |
| **最终原因确认** | 等Step 4完填 | （待小林确认） |
| **处理方式** | 补拍/恢复/排除/其他 | （待决定） |
| **关闭日期** | Step 7完成填 | |

## 四、影响范围评估模板（Step 5必写，粘贴到报告§六）

```
### 缺口 GAP-XXXXXX 影响评估

1. **敏感区域判定**：
   缺口位于 ⬜ 均匀来流区（低敏感） / ⬜ 边界层外缘（中敏感） / ⬜ 近壁区/分离区（高敏感）
   理由：___

2. **前后数据连续性检查**：
   缺口前最后一个有效值：y_prev = ___ mm
   缺口后第一个有效值：y_next = ___ mm
   线性插值估算缺口处：y_interp = ___ mm
   前后梯度突变比例：___ %（<10%为平缓，>50%为突变）

3. **两套结果对比**：
   | 结果类型 | 总误差（不含极端值） | 变化量 |
   |:---|:---:|:---:|
   | 直接排除缺口点 | ___ % | — |
   | 用线性插值替代 | ___ % | ±___ % |
   | 最坏情况假设（取包络线） | ___ % | ±___ % |

4. **结论可信等级**：
   ⬜ A 级（无影响，可信） / ⬜ B 级（轻微影响，仍可用） / ⬜ C 级（影响显著，需补证据）
```

## 五、允许带缺口出报告的条件（**满足全部才可出**）

✅ 缺口登记表所有字段已填写（除「关闭日期」外）

✅ 报告首页数据完整性标志 = ⚠️，且醒目位置标注「含待确认缺口」

✅ 报告§六已粘贴影响评估模板且填完

✅ 结论中**未出现**「最终」「确定」「结论性」等字样，改用「初步」「当前」「待补证」

✅ 状态追踪看板已更新

✅ 已通知小林且收到回复（哪怕是「先这么出，回头补」）

## 六、参考：各类型缺口典型影响速查

| 缺口类型 | 常见位置 | 对总误差典型影响 | 优先处理等级 |
|:---|:---|:---|:---:|
| 时序缺口 | 风洞切换工况前后 | ±0.5% ~ ±2% | 🟡 中 |
| 空间缺口（边界层内） | y/δ < 0.2 区域 | ±2% ~ ±8% | 🔴 高，必须补 |
| 空间缺口（自由流区） | y/δ > 0.5 区域 | ±0.2% ~ ±1% | 🟢 低 |
| 数据质量缺口 | 逆光/起雾照片 | 单点影响大，但可剔除 | 🟡 中 |
| 环境参数缺口 | 温湿度缺失 | 影响粘度→雷诺数，约±1% | 🟡 中 |
| 补备注缺口 | 照片编号错位 | 可能导致用错数据 | 🔴 高 |
