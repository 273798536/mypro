# 滑轮组张力阈值预警 · 交付说明（训练教练老唐版）

## 我（老唐）要做什么

每次算法值班人交来设备铭牌文件后，按下面三步走，就能把三件东西对给别人看：
设备铭牌 → 处理记录 → 页面摘要

---

## 第 1 步：准备好设备铭牌文件

把算法值班人交来的铭牌数据文件（.json 或 .csv）放到任意目录。
推荐命名：`铭牌编号_日期.json`，例如 `PL-A-01_20260614.json`。

**字段不管怎么写都没事**：系统会自动识别中英文、大小写别名。
常见别名清单：

| 标准字段     | 算法值班人可能写的名字                          |
|--------------|-------------------------------------------------|
| 张力         | tension / 张力 / 拉力 / 主绳张力 / 主线张力 等 |
| 时间/序号    | timestamp / 时间 / 采集时间 / seq / 序号 等    |
| 方向         | direction / 方向 / 受力方向 / sign / 符号 等   |
| 设备/传感器  | sensor_id / 传感器编号 / 铭牌编号 / id 等       |
| 阶段         | stage / 阶段 / 训练阶段 / phase 等              |

系统会记录下"这次是把哪个来源字段当张力用的"，放在处理记录里，对得上。

---

## 第 2 步：运行值班脚本

```bash
# 方式一：直接调用（推荐）
python3 -m tension_warning 铭牌文件.json --output-dir ./outputs

# 方式二：用值班脚本（带日志和退出码）
./scripts/run_tension_warning.sh 铭牌文件.json
```

运行完看控制台最下面一行的 TAG：

| TAG            | 含义                           | 我要做什么                                 |
|----------------|--------------------------------|-------------------------------------------|
| [正常]         | 数据正常，没检出问题           | 留档即可                                   |
| [预警]         | 检出预警点，尤其留意收尾段     | 看页面摘要的结论块 + 证据行               |
| [危险]         | 检出危险点                     | 立即通知算法值班人 + 看极值簇位置         |
| [方向挂起待确认] | 方向符号疑似写反，已暂停分析 | **不要给稳定结论**，把页面摘要转给算法值班人核对 |
| [加载失败]     | 文件坏/字段找不到/数据空       | 让算法值班人检查文件内容或补充字段别名    |

---

## 第 3 步：把三份文件对给别人看

脚本跑完会在 `outputs/` 下生成 3 份 JSON，一一对应：

| 文件名                              | 给谁看          | 对应物                                                                                                         |
|-------------------------------------|-----------------|--------------------------------------------------------------------------------------------------------------|
| `*_page_summary.json`              | 对外公示/社区  | 就是**页面摘要**：conclusions_block（结论块）、evidence_lines（数字从哪来）、overall_status（和文件说法一致的状态标记）|
| `*_process_records.json`           | 内部核对用     | 就是**处理记录**：四个阶段（加载/方向校验/分析/导出）各自的输入、参数、输出、备注，每一步都留痕                  |
| `*_full_report.json`               | 算法深入排查   | 包含上面两份 + 分析细节 + 方向细节 + **一致性校验**（保证页面状态和分析结论一致）                              |

### 对外怎么讲（不看代码版）

1. **状态在哪看**：打开 `page_summary.json`，`overall_status` 就是对外说的状态，
   `raw_status_marker` 是内部算法算出来的等级，两者永远一致（不一致的话 `full_report.json` 里的 `consistency_check.status_match` 会是 false）。

2. **数字从哪来**：`evidence_lines` 里一行行写死了：
   - 最大张力 = X，在第几条记录，来源字段叫什么
   - 预警阈值多少、危险阈值多少
   - 极值簇从第几条到第几条、持续几个点、是不是收尾段

3. **收尾风险怎么解释**：整体平均值可能"看起来正常"，
   但最后 15% 的收尾段如果峰值超整体均值 25% 或均值超整体 10%，
   `tail_hidden_risk` 会标 true，`tail_summary` 和结论块里会写原因。

4. **方向挂起怎么解释**：铭牌写的方向和张力实际走的趋势对不上，
   系统不瞎猜，直接挂起，算法值班人核对完方向后再提交一次就行。

### 举例对照

- **设备铭牌**：examples/nameplate_tail_risk.json（收尾段突然从 60 飙到 92）
- **处理记录**：看 `加载阶段` 里的字段映射 → 看 `分析阶段` 里的极值簇 #0 是第 13-15 条
- **页面摘要**：conclusions_block 里会写"收尾风险"，evidence_lines 给证据

## 关键设计原则（讲给听得懂的人）

- **不做平滑**：不对原始张力取滑动平均，极端值保留原样，怕平均把风险埋了
- **方向宁可挂起**：方向有歧义就暂停，不输出假稳定结论（默认策略，可通过参数改，但不推荐）
- **字段名全记源**：系统匹配到哪个来源字段都存在处理记录里，前后两次字段名不一样也能对上
- **状态内外一致**：页面摘要的状态标记和分析结论的等级做了一致性校验，full_report 里能查到
