# 平面机构运动演示 - 产品需求文档

## 1. 产品概述与目标

### 1.1 产品定位
平面机构运动演示是为地图编辑和画布管理场景设计的数据质量审查工具，主要服务于教学评审场景。该系统不追求华丽的界面效果，而是专注于数据导入后的异常检测、来源追踪和处理记录管理。

### 1.2 核心目标
- **异常检测能力**：能够从导入数据中筛选出比例尺错用、轨迹异常、设备清单错误等坏记录
- **来源可追溯性**：任何数据问题都能从结果追溯到源头和处理记录
- **数据一致性**：界面摘要与导出内容完全一致，避免"页面显示通过、文件显示待确认"的情况
- **处理唯一性**：避免重复导入和补录导致同一问题出现多份结论

### 1.3 使用场景
1. **日常入口**：图层管理界面，作为日常数据质量检查的入口
2. **月末/课前检查**：查看画布状态，确保能清晰解释数据处理情况
3. **评审演示**：向评审老师展示具体材料（轨迹记录、设备清单、比例尺错用）处理情况
4. **异常追溯**：验收时使用离线素材缺失记录进行倒查

## 2. 功能需求

### 2.1 数据导入与图层管理

#### 2.1.1 导入功能
- **支持格式**：支持轨迹记录、设备清单、比例尺标注等标准格式导入
- **图层组织**：导入数据按类型自动归类到对应图层
- **唯一性检测**：导入时检测重复数据，防止同一记录被多次导入
- **离线素材处理**：识别并标记离线素材缺失的记录

#### 2.1.2 图层管理界面
- **图层列表**：展示所有导入的图层，支持展开/折叠
- **日常入口**：图层管理作为日常检查的主要入口
- **快速筛选**：按状态（正常、异常、待处理）快速筛选图层
- **状态统计**：显示各类状态的数量统计

### 2.2 异常检测与筛选系统

#### 2.2.1 异常类型识别
- **比例尺错用**：检测比例尺配置错误或缺失的情况
- **轨迹异常**：识别运动轨迹数据中的异常点
- **设备清单错误**：检测设备清单中的数据不一致或缺失
- **离线素材缺失**：标记依赖的离线素材无法找到的记录

#### 2.2.2 筛选功能
- **状态筛选**：按通过、待确认、异常、缺失等状态筛选
- **类型筛选**：按异常类型筛选（比例尺、轨迹、设备清单等）
- **时间筛选**：按导入时间或处理时间筛选
- **来源筛选**：按数据来源进行筛选

### 2.3 详情查看与处理记录

#### 2.3.1 详情页功能
- **基本信息展示**：显示记录的完整信息和元数据
- **来源追溯**：展示数据的原始来源（文件名、导入时间、导入人）
- **处理历史**：记录所有处理操作（确认、修改、驳回等）
- **处理意见**：显示每个处理步骤的意见和备注

#### 2.3.2 处理操作
- **确认通过**：标记异常记录为已处理
- **修改数据**：允许修改异常数据并记录修改历史
- **驳回重提**：将问题记录驳回给上游处理
- **补充素材**：为离线素材缺失的记录补充素材

### 2.4 颜色规则与状态显示

#### 2.4.1 颜色规则定义
| 状态 | 颜色 | 说明 |
|------|------|------|
| 正常/通过 | 绿色 (#22c55e) | 数据符合规范 |
| 待确认 | 黄色 (#eab308) | 需要人工确认 |
| 异常/驳回 | 红色 (#ef4444) | 存在明显错误 |
| 离线缺失 | 橙色 (#f97316) | 依赖素材不可用 |
| 处理中 | 蓝色 (#3b82f6) | 正在处理中 |

#### 2.4.2 界面显示要求
- **统一颜色规范**：整个应用使用统一的颜色规则
- **状态一致性**：颜色显示与数据状态完全一致
- **可访问性**：确保颜色对比度符合WCAG标准

### 2.5 导出与数据一致性

#### 2.5.1 导出功能
- **完整导出**：导出所有记录及处理状态
- **筛选导出**：按条件导出选定的记录
- **格式支持**：支持CSV、JSON等标准格式导出
- **审计导出**：导出包含完整处理历史的审计报告

#### 2.5.2 数据一致性校验
- **界面-文件一致性**：确保导出内容与界面摘要完全一致
- **状态同步**：处理操作实时同步到导出文件
- **冲突检测**：检测并提示数据冲突

### 2.6 重复处理与补录管理

#### 2.6.1 重复导入检测
- **唯一性约束**：基于关键字段（如记录ID）检测重复
- **重复提示**：检测到重复时提示用户
- **覆盖或保留**：允许用户选择覆盖或保留原有数据

#### 2.6.2 补录处理
- **补录标识**：补录数据带有明确标识
- **结论统一**：避免同一问题出现多份结论
- **历史追溯**：补录操作记录完整的时间戳和操作人

## 3. 用户界面设计

### 3.1 整体风格
- **简洁实用**：界面不追求花哨效果，重点在于功能性和可读性
- **数据导向**：以数据展示为核心，减少装饰性元素
- **评审友好**：适合在评审场景下演示和使用

### 3.2 主要页面

#### 3.2.1 图层管理首页
- **入口位置**：作为日常入口放置在显眼位置
- **画布状态概览**：显示整体画布状态摘要
- **快速筛选栏**：提供状态和类型快速筛选
- **图层列表**：展示所有图层及其状态

#### 3.2.2 数据详情页
- **来源信息区**：展示数据来源和处理历史
- **详细信息区**：显示完整的记录信息
- **处理意见区**：展示所有处理意见和备注
- **操作按钮区**：提供确认、修改、驳回等操作

#### 3.2.3 导出报告页
- **导出预览**：预览导出内容
- **一致性检查**：显示数据一致性检查结果
- **导出选项**：选择导出格式和范围

### 3.3 交互设计
- **清晰的反馈**：每个操作都有明确的反馈
- **可逆操作**：关键操作支持撤销
- **批量操作**：支持批量确认、导出等操作

## 4. 数据模型

### 4.1 核心数据结构

#### 4.1.1 记录模型 (Record)
```typescript
interface Record {
  id: string;                    // 唯一标识
  type: RecordType;              // 记录类型（轨迹/设备/比例尺）
  source: DataSource;             // 数据来源
  status: RecordStatus;           // 记录状态
  data: RecordData;               // 记录数据
  offlineMissing: boolean;         // 离线素材是否缺失
  createdAt: Date;                // 创建时间
  updatedAt: Date;                // 更新时间
}
```

#### 4.1.2 处理记录模型 (ProcessingRecord)
```typescript
interface ProcessingRecord {
  id: string;
  recordId: string;               // 关联记录ID
  action: ProcessingAction;       // 处理动作
  operator: string;               // 操作人
  opinion: string;                // 处理意见
  timestamp: Date;                // 处理时间
  previousStatus: RecordStatus;   // 处理前状态
  newStatus: RecordStatus;        // 处理后状态
}
```

#### 4.1.3 状态枚举
```typescript
enum RecordStatus {
  NORMAL = 'normal',              // 正常
  PENDING = 'pending',            // 待确认
  ABNORMAL = 'abnormal',          // 异常
  OFFLINE_MISSING = 'offline_missing', // 离线缺失
  PROCESSING = 'processing'       // 处理中
}

enum RecordType {
  TRAJECTORY = 'trajectory',      // 轨迹记录
  DEVICE_LIST = 'device_list',    // 设备清单
  SCALE_ERROR = 'scale_error'     // 比例尺错用
}
```

## 5. 验收标准

### 5.1 功能验收
- [ ] 能够导入轨迹记录、设备清单和比例尺数据
- [ ] 导入后能自动识别并筛选出异常记录（比例尺错用、轨迹异常等）
- [ ] 详情页能完整显示来源信息和处理记录
- [ ] 颜色规则在界面上统一应用且准确
- [ ] 导出内容与界面摘要完全一致
- [ ] 重复导入和补录不会导致重复结论
- [ ] 能从结果追溯到来源和处理记录

### 5.2 评审验收
- [ ] 轨迹记录、设备清单和比例尺错用能放在同一轮复核中展示
- [ ] 评审老师能清晰看到处理的是哪批具体材料
- [ ] 离线素材缺失记录能用于倒查
- [ ] 画布状态能解释清楚

### 5.3 数据一致性验收
- [ ] 页面显示"通过"的文件内容也是"通过"状态
- [ ] 不出现页面显示通过、文件里写待确认的情况
- [ ] 导出报告包含完整的处理历史

## 6. 技术约束

### 6.1 性能要求
- 导入1000条记录响应时间不超过3秒
- 界面筛选操作响应时间不超过500毫秒
- 导出1000条记录不超过5秒

### 6.2 数据安全
- 所有操作需要记录操作日志
- 关键操作需要确认提示
- 数据删除需要二次确认

### 6.3 兼容性
- 支持主流浏览器（Chrome、Firefox、Safari、Edge）
- 响应式设计，支持不同屏幕尺寸
