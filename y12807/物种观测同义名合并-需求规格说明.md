# 物种观测同义名合并系统 - 需求规格说明

## 1. 项目概述

### 1.1 背景
物种观测同义名合并是生态调查工作中的核心数据处理环节。由于观测数据来源多样、物种命名存在异名现象、且病理备注等补充材料可能延迟到达，导致数据合并与复核过程复杂，需要系统化工具支撑。

### 1.2 目标
构建一套支持物种观测数据同义名合并、复核、审计追踪的处理系统，确保数据一致性、操作可追溯、结论可解释。

---

## 2. 核心功能需求

### 2.1 数据导入与启动

#### 2.1.1 数据导入
- 支持导入物种观测原始数据（含物种名、观测记录、图像标注、分组信息等）
- 支持导入同义名映射表
- 支持病理备注等补充材料的**延迟补录**（允许在合并流程启动后追加）
- 导入时记录数据批次号、导入时间、导入人

#### 2.1.2 合并任务启动
- 用户可选择数据批次发起同义名合并任务
- 合并过程基于同一批处理记录，确保分组统计与图像标注数据源一致

---

### 2.2 同义名合并与标注

#### 2.2.1 合并处理
- 系统根据同义名映射表自动合并物种观测记录
- 合并逻辑覆盖：观测计数合并、图像标注归并、分组统计重算
- **核心约束**：分组统计与图像标注必须基于**同一批处理记录**计算，禁止界面展示与报告导出使用不同数据源

#### 2.2.2 边界不清记录的解释说明
- 对于标注边界模糊、合并存在歧义的记录，结果旁需展示**解释说明**（1-2 句话）
- 解释说明用途：供生态调查员、老师、工程师向他人解释判断依据
- 解释内容来源：
  - 系统自动生成的判定理由（如同名异物判定依据、置信度等）
  - 人工标注时填写的备注

---

### 2.3 异常检测与查看

#### 2.3.1 阴性对照异常检测
- 系统自动检测阴性对照数据中的异常情况
- 异常记录标记后可被复核

#### 2.3.2 延迟数据的影响重算
- 当病理备注等补充材料延迟到达时（即使晚到半天），需支持**重算**相关判断
- 因补充材料导致原有结论失效的记录，需标记为"待重新复核"
- 历史结论需保留，不可直接覆盖

#### 2.3.3 异常查看
- 异常记录列表展示，支持按异常类型、严重程度筛选
- 每条异常记录支持**向下钻取**：从异常 → 复核意见 → 处理意见，形成完整追溯链

---

### 2.4 复核管理

#### 2.4.1 复核流程
- 低质量读段、异常记录、边界不清记录均可进入复核流程
- 复核意见字段：结论（通过/驳回/需补充）、理由、附件
- 复核状态流转：待复核 → 复核中 → 已复核 → （如需）重新复核

#### 2.4.2 复核意见修改与对比
- 已复核的记录允许修改复核意见
- 修改后**旧结论与新结论并排展示**，便于对比影响范围
- 对比内容包括：结论变化、理由变化、修改人、修改时间

#### 2.4.3 低质量读段复核审计
- 低质量读段若被**复核通过**，必须记录完整审计信息：
  - 谁修改的（操作人）
  - 什么时候修改的（操作时间）
  - 为什么修改（修改理由 / 复核意见）
- 审计记录不可删除、不可篡改

---

### 2.5 可追溯性

#### 2.5.1 异常追溯链
验收标准：**顺着一条异常往回查，能查到复核意见和处理意见**

追溯路径：
```
异常记录 → 关联的观测数据 → 复核意见（含历史版本） → 处理意见 → 操作人 / 时间
```

#### 2.5.2 操作日志
- 所有关键操作均记录日志：导入、合并、复核、修改、导出
- 日志字段：操作人、操作时间、操作类型、操作对象、变更前后值

---

### 2.6 结果导出

- 支持导出合并结果报告
- 支持导出复核意见汇总
- 支持导出异常记录清单
- 导出数据与界面展示数据**同源**，确保一致性

---

## 3. 数据模型概要

### 3.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| 观测记录 | 原始物种观测数据 | 记录ID、物种名、观测值、数据来源、批次号 |
| 同义名映射 | 物种同义名关系 | 标准名、异名、置信度、判定依据 |
| 合并结果 | 同义名合并后的结果 | 结果ID、标准物种名、合并后统计值、数据批次 |
| 异常记录 | 检测出的异常 | 异常ID、关联记录ID、异常类型、异常描述、状态 |
| 复核意见 | 复核记录 | 复核ID、关联对象、结论、理由、复核人、复核时间、版本号 |
| 操作日志 | 审计追踪 | 日志ID、操作人、操作时间、操作类型、变更详情 |
| 数据批次 | 数据批次管理 | 批次号、导入时间、导入人、数据范围、状态 |

### 3.2 数据一致性约束
- 分组统计、图像标注、报告导出**必须关联同一数据批次**
- 复核意见支持多版本，最新版本标记为"当前有效"
- 所有版本均可追溯，不可物理删除

---

## 4. 用户操作流程

### 4.1 标准流程

```
启动系统
    ↓
导入数据（观测数据 + 同义名映射表）
    ↓
发起同义名合并任务
    ↓
查看合并结果 + 异常检测结果
    ↓
对异常/低质量记录进行复核
    ↓
（可选）修改复核意见 → 系统保留历史版本
    ↓
导出结果报告
```

### 4.2 补充材料到达后的流程

```
病理备注等补充材料到达
    ↓
补录数据（关联原批次）
    ↓
触发重算 / 标记受影响记录
    ↓
受影响的原结论标记为"待重新复核"
    ↓
重新复核 → 生成新版本复核意见
    ↓
新旧结论并排展示对比
```

---

## 5. 非功能需求

### 5.1 可追溯性
- 任何一条异常记录均可回溯到对应的复核意见和处理意见
- 操作人、时间、理由三要素完整

### 5.2 数据一致性
- 界面展示、统计报表、导出报告使用同一批处理记录
- 不存在"界面算一套、报告算一套"的情况

### 5.3 可解释性
- 边界不清的记录必须附带解释说明
- 解释说明应简洁（1-2 句话）、可用于对外讲解

### 5.4 审计安全
- 复核修改历史不可删除、不可篡改
- 低质量读段复核通过必须留痕

---

## 6. 验收标准

### 6.1 功能验收清单

| 编号 | 验收项 | 验收方法 |
|------|--------|----------|
| A-01 | 启动系统并导入数据 | 执行导入操作，确认数据批次号生成 |
| A-02 | 发起同义名合并 | 合并完成后，分组统计与图像标注数据一致 |
| A-03 | 查看异常记录 | 异常列表可正常展示，每条异常可钻取详情 |
| A-04 | 边界不清记录有解释 | 随机抽取边界记录，确认结果旁有1-2句说明 |
| A-05 | 复核意见录入 | 对异常记录提交复核意见，状态正确流转 |
| A-06 | 复核意见修改与对比 | 修改已有复核意见，确认新旧结论并排展示 |
| A-07 | 低质量读段复核留痕 | 低质量读段复核通过后，历史中可查人/时/因 |
| A-08 | 异常追溯链 | 从一条异常往回查，可依次查到复核意见和处理意见 |
| A-09 | 补充材料延迟到达 | 补录病理备注后，原结论标记为待重算，历史保留 |
| A-10 | 结果导出 | 导出数据与界面展示数据一致 |

### 6.2 核心验收路径
> 顺着一条异常往回查，能查到复核意见和处理意见——才算顺。

## 7. 说明文档要求

用户使用说明文档**避免写成宣传页**，需聚焦以下操作步骤：

1. **启动** — 如何启动系统、进入合并模块
2. **导入** — 如何导入观测数据和同义名表
3. **查看异常** — 如何查看异常记录及其详情
4. **导出结果** — 如何导出合并结果和复核报告

每个步骤配操作截图和简要说明即可。
