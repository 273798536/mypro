# 🏮 夜市外摆容量复核系统

> 给社区运营阿宁专属的「夜市外摆容量复核」工作台，解决：GIS点位翻查费劲、旧版意见被新表盖掉、刷新丢状态、重复投诉来不及确认等一堆老问题。

---

## 🚀 快速开始（阿宁，先看这里）

### 第 1 步：装依赖（第一次跑才需要）

```bash
npm install
```

### 第 2 步：先扫一眼今天的异常队列（推荐每次先跑这个）

```bash
npm run queue
```
运行后终端会打印：
- 高危/中危/低危 各有多少条
- 今天优先要啃的骨头（重复投诉那几个高危项）
- 每条异常是什么点位、什么问题

### 第 3 步：启动复核工作台（这是你每天干活的地方）

```bash
npm run review
```

浏览器会自动打开 `http://localhost:5173/#/review`，如果没打开就手动粘过去。

> 🔖 也可以用标准命令：`npm run dev`（和 `npm run review` 效果一样，就是少了欢迎语）

## 🗂️ 三个主要页面怎么用

### 📍 页面 1：复核工作台（`/review`）
这是你每天待得最久的地方，从上到下四块区域：

| 区域 | 解决的痛点 |
| --- | --- |
| **顶部筛选条** | 行政区/街道/类型/状态/关键词/重复投诉/异常点位，**刷新不会丢**，浏览器关了再开也记住 |
| **左上图 GIS 点位** | 红黄绿灰四色标记，红点=争议或重复投诉，带红点徽标=在异常队列里，点标记直接进详情 |
| **左下表 点位列表** | 带异常标记，点击即选中，和 GIS 图联动 |
| **右上 复核详情（核心）** | 5 个 Tab 全是精华，看下一节 |
| **右下 关联异常** | 当前点位挂了哪些异常，点击跳完整异常队列 |

#### 🔍 复核详情的 5 个 Tab

1. **基本信息**
   - 核定容量 / 当前摆位 / 建议容量（可改，历史自动留痕）
   - **如果是重复投诉点位 → 自动弹红色提醒**：必须先填"待确认原因"和"影响范围"，不让你急着算完
   
2. **复核意见**
   - ✅ **旧版意见保留在最上方**（米黄色块，有版本号 V1），不会被新表盖掉，随时回溯
   - 中间是你现在写的人工备注（自动保存、刷新不丢）
   - 下方是"本次版本修改轨迹"，每条写清楚"什么字段从啥改成啥、谁改的、几点改的"，周一早会直接念

3. **材料附件**
   - 每个点位标配一份复核材料包：`GIS点位数据` + `一条名称不一致` + `一份后补说明`，量少也要像真活
   - 材料类型自动打色标，可补充上传

4. **现场照片**
   - 补录照片时**必须填改动说明、补录前判断、补录后调整**
   - 提交后系统自动：① 在 GIS 点位加标记 ② 在异常队列加一条"补录照片后：xxx"的记录 ③ 历史变化同步

5. **历史变化**
   - 周一早会跟主管复盘时直接用这个 Tab
   - 上面是时间线：谁几点做了什么操作、改了哪些字段、字段值前后对比（红改绿）
   - 下面是版本对比卡片 V1 vs V2，一目了然

### ⚠️ 页面 2：异常队列（`/queue`）

- 支持按异常类型/等级/状态/关键词筛选
- 默认排序：高危优先 > 中危 > 低危
- 每行三个操作：跳转复核 / 标记解决 / 编辑备注
- **核心五类异常**：
  - 🔁 **重复投诉**（高危）：同一点位多条投诉，疑似同一批人
  - 🏷️ **名称不一致**（低危）：材料上的名字和系统登记对不上
  - 📊 **容量超限**（中危）：实际摆位超出核定
  - 📷 **照片缺失**（中危）：没现场照片不允许核定
  - 🤔 **待人工确认**（高危）：商户对复核结果有争议

### 📅 页面 3：历史复盘（`/history`）
周一早会专属视图：
- 顶部本周复核统计卡片（总数 / 已确认 / 异常 / 重复投诉）
- 左列全量操作时间线，按时间倒序
- 右列重点案例表（重复投诉排最前），点击跳详情
- 底部「人工确认前后典型对比」（南京东路案例），直接给主管讲这个就够

## 🔁 核心功能设计亮点（对应你吐槽的每一个痛点）

| 痛点 | 系统里怎么解决的 |
| --- | --- |
| 每次都要从 GIS 点位翻起 | 地图按"已确认/复核中/待复核/争议"四色标，异常点位多一个红点徽标，异常列表跳转即定位 |
| 旧版意见被新表盖掉 | 复核意见 Tab 永远先展示 V1 的旧意见（带版本号），新旧意见分区展示，且有完整版本对比卡片 |
| 刷新丢筛选条件 / 备注 / 队列 | `localStorage` 持久化，筛选条、人工备注、异常队列过滤项各自独立保存，关浏览器也不丢 |
| 准备材料东拼西凑 | 每个点位标配"GIS + 名称不一致 + 后补说明"三件套，材料面板有专门的上传入口和类型标签 |
| 重复投诉没核实就被算完了 | 只要点位带 `duplicateComplaint` 标记就自动弹红色告警，必须填"待确认原因+影响范围"，不填不让提交 |
| 补了照片说不清改了啥 | 补录表单强制要求"改动说明 + 补录前后判断"，提交后 GIS 标记和异常队列同步追加改动说明 |
| 人工确认前后讲不清楚 | 历史变化 Tab + 历史复盘页，时间线+对比表+前后值红改绿标注，主管一眼就懂 |
| 现场收到一堆材料不知道怎么理 | 每种材料有固定类型标签（GIS/名称不一致/后补说明/照片），系统帮你按类整理归档 |

## 📦 技术栈 & 目录

```
Vue 3 + TypeScript + Pinia + Element Plus + Leaflet（GIS地图）
```

```
src/
├── components/
│   ├── FilterBar.vue           # 顶部筛选条（带持久化）
│   ├── GisMap.vue              # Leaflet GIS 地图
│   ├── PointList.vue           # 点位列表（联动地图）
│   ├── ReviewDetail.vue        # 复核详情总容器（5个Tab）
│   ├── MiniAbnormalQueue.vue   # 右侧关联异常迷你面板
│   └── detail/                 # 详情5个Tab子组件
│       ├── BasicInfo.vue       # 基本信息+重复投诉确认
│       ├── ReviewOpinion.vue   # 复核意见（旧版保留+修改轨迹）
│       ├── MaterialPanel.vue   # 材料附件（三件套）
│       ├── PhotoPanel.vue      # 现场照片（补录改动说明）
│       └── HistoryPanel.vue    # 历史变化对比
├── views/
│   ├── ReviewPage.vue          # 复核工作台
│   ├── AbnormalQueue.vue       # 异常队列页
│   └── HistoryPage.vue         # 周一早会历史复盘
├── store/review.ts             # Pinia 状态（含持久化）
├── mock/data.ts                # 12个点位的模拟数据（含3个重复投诉）
├── types/index.ts              # TS 类型定义
└── router/index.ts             # 路由
scripts/
├── start-review.js             # npm run review 的欢迎语脚本
└── check-queue.js              # npm run queue 的终端异常报告
```

## 📝 给阿宁的每日工作流（建议打印贴工位）

```
09:00  🌅 开工
        ├─ 跑 npm run queue → 扫一眼今天要处理的异常
        └─ 跑 npm run review → 打开系统

09:15  🔴 处理高危异常（重复投诉那3个）
        ├─ 点进异常 → 跳转复核 → 基本信息 Tab 填"待确认原因 + 影响范围"
        ├─ 写人工备注 → 保存（不用怕丢，刷新还在）
        └─ 标记异常为"处理中"

10:30  📍 剩下的点位
        ├─ GIS 地图按颜色点 → 旧版意见先读一遍 → 写当前版意见
        ├─ 材料 Tab 检查三件套是否齐全 → 不齐就补
        └─ 照片 Tab 看看是否要补录（补录一定要写改动说明！）

12:00  🥣 午饭前
        └─ 刷新一下页面 → 核对所有状态都在（不丢就算过关）

14:00  🚶 现场跑点位拍照
        └─ 回来补录进照片 Tab，一定要填"补录前后对比"

16:30  ✅ 收尾
        ├─ 所有完成的点位 → 点"提交复核"
        ├─ 异常队列 → 处理完的"标记解决"
        └─ 切到历史复盘页 → 快速浏览一遍，周一讲的素材就有了

周一早会 🎯
        └─ 打开历史复盘页 → 讲"南京东路"那个典型案例的前后对比就够
```
