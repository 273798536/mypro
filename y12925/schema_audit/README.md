# 工具参数 Schema 审计系统

## 一句话说明
跑一批能复现的 schema 审计样例，看图、看表、看文字说明三者对不对得上；核心是**评测回放 + 人工修正**要稳，**灰度对比**把结论拉回来源材料。

---

## 快速开始（从空目录跑通）

### 方式一：一键启动（推荐）
```bash
cd schema_audit
./start.sh
```
脚本会自动：建虚拟环境 → 装依赖 → 启服务。

### 方式二：手动启动
```bash
cd schema_audit
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py --server.port=8501
```

### 启动后
- 浏览器打开：**http://localhost:8501**
- 第一份样例位置：`data/sample_schema_records.json`（系统启动时自动加载）

## 这版审计系统覆盖的点

| 模块 | 负责什么 | 你会看到什么 |
|------|----------|--------------|
| **评测回放** | 重跑历史评测，校验工具参数 schema 的必填/类型/枚举是否合规 | 回放对比表（原结果 vs 重放结果）、通过率趋势图、失败原因分布 |
| **人工修正** | 追踪标注员的修正记录，清洗空值/重复/备注混写 | 修正流水表、脏数据清洗前后对比、修正意见聚合 |
| **灰度对比** | 把结论回溯到来源材料，确认不是拍脑袋 | 来源材料引用链、结论溯源图、灰度前后通过率差异 |
| **导出对账** | 页面摘要和导出文件结论必须一致 | 一致性校验报告、差异高亮清单 |
| **评审分类** | 模型评审结果分两栏，一眼分清 | 「直接可用」绿栏 + 「需平台工程师复核」红栏，带风险标签 |

## 样例数据说明（故意做脏的）

`data/sample_schema_records.json` 里包含 30 条 schema 记录，故意掺了：
- **空值**：`description: null`、`enum: []`
- **重复**：同一个 `tool_name + param_name` 出现多次，标注员各标各的
- **备注混写**：`required` 字段里混进了 "必填 注意和XX对齐" 这种备注文字
- **结论打架**：界面摘要写「通过」，标注记录写「待确认」

这些正好覆盖日常标注里最常见的乱子。

---

## 导出文件

跑出来的审计报告、对比表会放在 `exports/` 目录下，格式：
- `exports/audit_report_{timestamp}.xlsx` — 多 Sheet 完整报告
- `exports/review_summary_{timestamp}.json` — 评审分类摘要

## 复核时怎么用

1. 打开界面 → 默认加载第一份样例
2. 先看「总览仪表盘」：图（通过率趋势）、表（失败 Top5）、文字（本轮审计结论）三者扫一眼对不对
3. 切到「评测回放」Tab：看重放和原结果的差异行有没有被高亮
4. 切到「人工修正」Tab：看脏数据清洗前后计数，确认空值/重复处理对了
5. 切到「灰度对比」Tab：顺着来源材料引用链点回去，看结论能不能溯源
6. 点右上角「导出报告」，再对照界面摘要，确认没有「页面说通过文件写待确认」
7. 最后看「评审分类」：绿栏直接给模型用，红栏截图丢给平台工程师
