# 数独候选削减器 使用说明

## 1. 启动服务

```bash
cd /Users/mac/pro/solo/workspaces/y12724
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

启动后访问 http://localhost:8000/ 可看到服务信息，http://localhost:8000/docs 可查看并调试所有接口。

所有数据保存在同目录的 `sudoku_reducer.db`（SQLite），重启服务后历史处理痕迹仍然存在。

---

## 2. 导入候选数据

支持 xlsx / csv / json 三种格式。

**文件字段要求（大小写不敏感）：**
- `name` / `候选名称` / `名称`：候选名称（可选，为空会自动用行号命名）
- `value` / `数值` / `值`：数值
- `unit` / `单位` / `计量单位`：单位
- `boundary` / `边界` / `边界样例`：是否为边界样例（可选，true/false）

**导入方式：**
打开 http://localhost:8000/docs 找到 `POST /api/import`，点「Try it out」：
- `file`：选择要上传的文件
- `batch_name`：批次名称（可选，默认用文件名+时间）
- 点「Execute」

导入成功后会返回：
- `batch_id`：批次 ID，后续接口都要用到
- `valid_count` / `invalid_count`：可用/不可用记录数
- `issues`：异常清单（单位缺失、数值缺失等逐条列出，不会藏在汇总里）

---

## 3. 查看异常（重点：单位缺失）

**方法一：接口查询**

调用 `GET /api/batches/{batch_id}/issues`，返回：
- `summary.unit_missing_count`：单位缺失总条数
- `unit_missing_records`：每条单位缺失记录的行号、名称、拦截原因

也可以用 `GET /api/batches/{batch_id}/records?only_invalid=true` 列出所有不可用记录。

**方法二：单条记录详情**

调用 `GET /api/records/{record_id}` 可查看：
- `block_reason`：具体拦截原因
- `status_history`：状态变更历史（谁、什么时候、改了什么、备注）
- `calculation_drafts`：计算草稿历史版本和差异

---

## 4. 补录缺失字段 & 状态推进

### 4.1 补录单位（解除拦截）

调用 `PATCH /api/records/{record_id}/fix`，传 `unit=万元` 等参数即可。
补录后如果数值和单位都齐了，记录会自动从 `blocked` 退回到 `pending_review`，状态历史会保留补录痕迹。

### 4.2 状态推进

调用 `PATCH /api/records/{record_id}`，传：
- `status`：目标状态（待复核 → 复核中 → 已确认 等，非法跳转接口会报错）
- `reviewed_by`：操作人
- `note`：复核备注

合法状态流：
```
pending_review(待复核) → reviewing(复核中) → confirmed(已确认)
                       ↘ rejected(已驳回) / blocked(已拦截)
blocked / rejected → reopened(已重开) → reviewing
confirmed → exported(已导出) 或 reopened
```

### 4.3 批次整体推进

调用 `PATCH /api/batches/{batch_id}` 可更新批次状态（如 processing / completed）并加备注。

## 5. 计算草稿补录 & 历史对比

调用 `POST /api/calculations` 新增计算草稿，传：
- `record_id`：对应记录 ID
- `formula_name`：公式名（如「评分」）
- `formula_expr`：公式表达式（如 `value * 0.8 + 10`，可用字段包括 `value` 及原始数据中所有数值字段）
- `draft_value`：草稿值（可选，手动录入会覆盖公式计算）
- `is_supplement`：是否为补录
- `diff_note`：备注

同一公式第二次创建时会自动生成 `v2` 新版本，并在 `diff_note` 里写入「相对 v1 上升/下降 X」的历史对比。
草稿一旦录入，记录会自动从 `pending_review` 前进到 `reviewing`。

调用 `PATCH /api/calculations/{draft_id}` 也可以修改旧草稿，同样会生成新版本而不是覆盖。

调用 `GET /api/records/{record_id}/calculations` 可查看某条记录的全部草稿版本。

---

## 6. 边界样例延迟到达

调用 `POST /api/batches/{batch_id}/boundary-append` 上传后期到达的边界样例文件。
系统不会悄悄覆盖旧结论，而是：
1. 新记录标记 `boundary_arrived_late=true`
2. 对同名的已确认/复核中记录，自动退回到 `reviewing`
3. 在返回的 `affected_records` 中列出每条受影响的记录、原本的状态、具体受什么影响
4. 每条受影响记录的 `affected_conclusions` 字段也会同步记录受影响原因

---

## 7. 导出报告（给学生看）

调用 `GET /api/batches/{batch_id}/export` 下载 Excel 报告。报告包含 4 个 sheet：

| Sheet | 内容 |
|---|---|
| **报告摘要** | 批次概览 + 给学生的重点提示 |
| **候选清单** | 全量记录。**红色整行高亮 = 不可用**（第 7 列详细说明「为什么被拦截」，比如单位缺失会解释口径不一致无法汇总）；**黄色高亮 = 受边界样例影响需重审** |
| **不可用记录详情** | 单独列出所有不可用记录的问题类型和详细说明，学生只看这一页就知道哪些不能用、为什么不能用 |
| **计算草稿历史** | 每条记录所有公式的所有版本，含「相对上版差异」列 |

即使学生只打开导出的 Excel，不登录系统，也能通过红色高亮 + 详细说明列，明白单位缺失的记录为什么被拦下来。
