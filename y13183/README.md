# 冷却塔水滴误差归因

设备工程师老何专用。先跑第 1 条命令，再看第 2 条输出的异常队列，按条目处理。

---

## 快速开始（老何看这里就够了）

### 第 1 步：跑归因分析
```bash
python3 run.py run
```

跑完屏幕直接打印异常队列，同时生成三份文件：
- `reports/运行编号_report.md` — 完整报告（含统计、公式、明细表、异常、边界样本）
- `output/运行编号_bundle.json` — 数据包（筛选条件、统计、明细表、异常队列同根同源）
- `output/运行编号_anomaly_queue.txt` — 异常队列精简版，打印出来揣兜里也行

### 第 2 步：看异常队列
跑完 `run` 屏幕会直接打印。任何时候再看一眼：
```bash
python3 run.py queue
```

每条异常下面写好了下一步怎么做，照做就行。

### 其他常用
```bash
python3 run.py status      # 看系统当前状态、最近跑了哪次、参数多少
python3 run.py params      # 看能调哪些参数
```

## 参数调一档再复算

觉得误差阈值太松或太紧，或者边界修正系数要改，直接加参数：

```bash
# 误差阈值从默认 2.0% 调到 1.5%
python3 run.py run --threshold 1.5

# 低端边界修正系数从 0.94 调到 0.92，高端从 0.95 调到 0.96
python3 run.py run --low-corr 0.92 --high-corr 0.96

# 同时调几档
python3 run.py run --threshold 1.5 --low-corr 0.92 --temp-corr 0.10
```

报告里会列出：**本次参数、上次参数、差值**，以及参数为什么让结果变化的说明。

## 结果同一根同源保证

每次 `run.py run` 生成的 **筛选条件、统计数字、明细表、异常队列** 都来自同一份 `AttributionResult`，写在同一个 JSON bundle 里（`output/*_bundle.json`），不会对不上。

重启或重跑以后，`state/persistent_state.json` 会保存：
- 历史备注（每次运行的摘要）
- 当前状态（每台设备的一句话总览）
- 异常队列（全部条目、处理状态、下一步）
- 参数历史（调过几档都留档）

所以关了终端再开，`python3 run.py queue` 还能看见之前的异常。

## 采样缺口怎么处理

报告里和异常队列里都会写成人能照着做的下一步，比如：
1. 确认通讯是否恢复，查看网络日志；
2. 找到对应时段旁通阀人工记录或压差读数；
3. 若无人工记录，用前后1小时数据线性插值补填；
4. 在系统备注中标注补填来源。

## 边界样本为什么影响结果

报告第五章专门解释：高低端流量超出校准线性区间时，水滴计数器采样频率或涡轮转速非线性，需要乘修正系数 K_boundary。
这个系数一改，修正后流量 Q_corr 直接变，误差率 ε 和归因分布自然跟着变。报告里会把前后参数差值列出来。
