# 工业视觉误判回放

面向产线质检的误判复核台：回放某版本视觉模型的判断结果，定位「同一样本被重复评测」与「把结论拉偏的样本」。参数名、失败提示、导出状态在版本间保持稳定，可直接放进日常脚本运行。

## 快速开始

```bash
npm install
npm run dev     # 浏览器访问 http://localhost:5173
npm run build   # 产物 + 类型校验
```

> 数据为内置 Mock（36 条样本，跨版本重复评测），见 [samples.ts](file:///Users/mac/pro/solo/workspaces/y13318/src/data/samples.ts)。替换为真实接口时保持 `Sample` 字段稳定即可。

## 两三步操作

1. **看版本说明条**：顶部确认版本与「本版改变判断」条数；没有就点开补一条（存本地）。
2. **收窄范围 + 看去重对比**：用「版本 / 材料 / 筛选」收窄，指标卡的「去重前 / 去重后」差距越大，说明重复评测越多。
3. **看拉偏样本榜 → 导出**：点开 Top 样本确认重复标记与对误判率的贡献，再导出截图说明归档。

## 坏材料来了该看哪里（重点）

现场发现坏材料（漏检 / 误判）时，按这个顺序最快定位元凶：

1. **筛选 → 仅误判/漏检**：列表只剩坏材料，行首 `◆` 表示该样本被重复评测过。
2. **拉偏样本榜 Top**：置信度越高却判错的样本，越可能是把结论拉偏的元凶，点开看「对误判率贡献」与「重复次数」。
3. **详情抽屉「重复评测标记」**：若 `跨版本重复` 且两次结论不同 → 是版本回归，看详情里的「本版改变判断」琥珀条（旧判断 → 新判断）。
4. **仍不确定**：把版本切到「全部版本」，对比同一坏样本在 `v2.4.0 / v2.4.1` 的预测差异。
5. **归档**：导出「截图说明(HTML)」，导出前已自动校验页面状态与文件一致，不一致会报 `E_EXPORT_MISMATCH` 并阻断。

## 稳定契约（脚本依赖，版本间不改名）

URL 参数：

| 参数 | 取值 | 说明 |
|------|------|------|
| `version` | `v2.4.0` / `v2.4.1` / `all` | 评测版本 |
| `run` | 评测批次 | 透传显示 |
| `filter` | `all` / `duplicate` / `misjudged` / `skewed` | 样本筛选 |
| `sample` | 样本ID | 打开详情抽屉 |
| `export` | `json` / `report` | 触发导出 |
| `lang` | 语言 | 预留 |

示例（日常脚本一键跑）：

```
http://localhost:5173/?version=v2.4.1&filter=duplicate&export=report
```

失败提示格式：`[ERROR_CODE] 可读说明`（文案可变，错误码不变）。

错误码：

- `E_VERSION_NOT_FOUND` — 版本不存在
- `E_SAMPLE_NOT_FOUND` — 样本不存在
- `E_DUPLICATE_GROUP_BROKEN` — 重复组数据异常
- `E_EXPORT_MISMATCH` — 导出文件状态与页面不一致
- `E_FILTER_INVALID` — 筛选参数非法
- `E_VERSION_NOTE_MISSING` — 版本说明缺失

## 版本说明

顶部版本说明条 → 打开面板 → 补备注与「本版改变判断」（样本ID + 旧判断 → 新判断）→ 保存（本地 localStorage）。评审会前临时补一条即可，复核台版本说明条会即时刷新。
