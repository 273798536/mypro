# 播客片头清单归档

舞台通道表 × 曲目表 对齐与追溯系统

## 三步操作

### 1. 启动服务
```bash
npm install
npm run dev
```
打开 http://localhost:3000

### 2. 自动对齐
点击页面上的 **「🚀 自动对齐」** 按钮，系统会自动将舞台通道记录与曲目表按顺序配对。

### 3. 处理异常并归档
- 对异常条目点击 **「改判」** 或 **「授权」** 修正对齐
- 确认无误后点击 **「归档」** 完成清单

---

## 🔍 坏材料排查指南

### 遇到文件名不对 → 看哪里？
1. 查看 `alignmentIssues` 字段
2. 对比舞台 `originalFilename` vs 曲目表 `expectedFilename`
3. 通常是录音师存文件时加了 `_v2`、`_final` 等后缀

### 遇到「时码偏半拍」 → 不是含糊警告！
1. 点击条目上的 **「▼ 查看原始说法」**
2. 查看 `rawDescription` 原始记录描述
3. 查看 `engineerNote` 录音师备注（老许会写在这里）
4. 典型原始说法示例：
   > "CH3 主题音乐 设备重启后第一轨 时码偏半拍 约20ms 已在录音日志标注"

### 遇到晚到附件 → 看哪里？
1. 状态标记为 `late_arrival`（黄色徽章）
2. 查看 `receivedAt` 实际接收时间
3. 查看 `engineerNote` 了解晚到原因
4. 示例：
   > "晚到！导播临时改的版本，彩排后才交过来"

### 评审会复盘 → 看历史
1. 点击任一条目的 **「历史」** 按钮
2. 可追溯每一次状态变更的：
   - 来源（自动对齐/人工改判/授权/系统）
   - 操作人
   - 变更前后对比
   - 原因说明

## 数据说明

### 试跑数据包含
| 编号 | 问题类型 | 备注 |
|------|----------|------|
| CH1 | 正常匹配 | 开场音乐 |
| CH2 | 文件名不匹配 | `_v2` 后缀 |
| CH3 | 时码偏半拍 | 约20ms，含原始说法 |
| CH4 | 正常匹配 | 赞助商广告 |
| CH5 | 晚到附件 | 彩排后送达 |

### 状态流转
```
pending → matched → authorized → archived
        → mismatch_* → rejudged → authorized → archived
        → late_arrival → authorized → archived
```
