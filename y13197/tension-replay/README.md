# 滑轮组张力参数回放

评审会专用的张力参数回放分析工具。

## 快速开始

```bash
npm install
npm run dev
```

打开浏览器访问显示的地址即可。

## 三步操作

**1. 加载数据**

点击「加载示例数据」快速体验，或点击「上传传感器日志」上传 JSON / CSV 文件。

> 字段名前后不一致也没关系，系统会自动识别映射。

**2. 看结果**

页面上方是**摘要**和**统计**，中间是**张力曲线图**，下方是**跳变分析**和**明细数据**。所有数据来自同一套分析结果，数字对得上。

**3. 筛数据**

左侧筛选面板可以按材料、滑轮组、处理状态过滤，也可以只看跳变点。

## ⚠ 坏材料来了看哪里？

当怀疑有坏材料或数据异常时，按以下顺序排查：

| 步骤 | 看哪里 | 看什么 |
|------|--------|--------|
| 1 | **页面顶部摘要** | 一眼看整体状态：正常/警告/危险，异常数量有多少 |
| 2 | **跳变分析面板** | 跳变原因分布图：是「单位不一致」「材料名不一致」还是「阈值波动」 |
| 3 | **左侧筛选条件** | 勾选「极端值」「待确认」状态，缩小排查范围 |
| 4 | **明细表 → 详情** | 点记录左侧的「详情」，看原始数据、来源字段、处理状态原因 |
| 5 | **明细表 → 修改历史** | 小宋临时改过的判断都存在这里，下一班同事能看到来龙去脉 |

### 常见跳变原因对照

- **单位不一致**：检查传感器日志的单位配置，是否存在 N 和 kN 混用
- **材料名称不一致**：同一种材料有不同编号或名称，需核对物料表
- **阈值波动**：可能是材料内部缺陷或传感器瞬时干扰，需结合工艺判断

### 数据来源在哪看？

每条记录的「详情」面板里都有：
- **源文件**：数据来自哪个文件
- **源字段**：映射到了原始日志的哪些字段名
- **原始数据**：完整的原始 JSON 数据

> 即使项目经理交来的日志字段名变了，这里也能追溯到来源。

## 处理状态说明

| 状态 | 含义 | 说明 |
|------|------|------|
| 正常 | 正常通过 | 在合理范围内的记录 |
| 疑似噪声 | 偏离均值 3σ 以上 | 可能是传感器瞬时干扰 |
| 极端值 | 偏离均值 5σ 以上 | 需重点关注，很可能有问题 |
| 待确认 | 超出正常范围 | 样本不足或边界情况，需人工确认 |
| 人工修改 | 被人工改过状态 | 修改历史可查，谁改的、改了什么都有记录 |

## 项目结构

```
src/
├── types/           # 类型定义
├── utils/
│   ├── fieldMapper.ts    # 字段映射（兼容不同字段名）
│   ├── dataParser.ts     # 数据解析
│   ├── analyzer.ts       # 分析逻辑（噪声/极端值/跳变检测）
│   └── history.ts        # 修改历史（localStorage 持久化）
├── components/      # UI 组件
├── data/
│   └── sampleData.ts     # 示例数据
├── App.tsx          # 主应用（统一数据源）
└── App.css          # 样式
```
